## 2. 핵심 설계 판단 — 커리큘럼 단계 = 회독 축 = 기존 모드 탭

앱의 AI 학습 모드 탭([AILearning.jsx:2706](../viewer/src/AILearning.jsx#L2706))이 강사 커리큘럼과 이미 1:1로 대응한다.

| 모드 탭 | 기존 설명 | 대응 커리큘럼 | 분량 |
|---|---|---|---|
| 📖 이론 | 처음 배움 | 기본이론 | 302h |
| 🧠 심화 | 판례·함정 | 심화이론 | 202h |
| ✏️ 문제풀이 | 기출 풀이 | 문제풀이 | 249h |
| ⚡ 복습 | 핵심 압축 | 특강(FINAL) | 44h |
| 🎯 진단 | OX 5문제 | 모의+핵심 | 117h |

**채택안: C+B 조합**
- **입력(무엇을 배울지)** = 기존 모드 탭 그대로. 탭에 따라 주입되는 강의 필기가 바뀐다. → 새 UI 없음
- **상태(몇 회독인지)** = 과목 헤더에 회독 진척 배지 신설. → `경제학 2회독(심화) · 47관 중 31관 · 다음: 제3관 수요의 탄력성`
- **게이팅** = 강제하지 않음. 1회독 미완 관에서 🧠심화를 누르면 "기본이론 먼저 볼까요?" 안내 1줄만.

기각안:
- **A. 단계 탭 2줄 추가** — 5모드 × 4단계 = 20종 조합, "심화 모드 + 1회독" 같은 모순 발생
- **B 단독. 과목당 회독 1회 선택** — 특정 관만 앞서 나가는 게 불가

> 용어 주의: 앱의 `stage`는 **1차/2차**를 뜻하는 기존 변수다([AILearning.jsx:1599](../viewer/src/AILearning.jsx#L1599)).
> 회독 축은 **`phase`** 라는 새 이름을 쓴다. 두 축은 직교한다.

## 3. 반드시 선행해야 할 데이터 구조 변경

현재 진척은 관 하나당 레코드 하나뿐이라 회독을 구분할 수 없다.

```js
// AS-IS — aiLearningStore.js, localStorage 'ailearn-mastery'
{ [leafId]: { coverage, accuracy, status, last_studied, next_review, srs_box } }

// TO-BE
{ [leafId]: {
    phases: {
      basic: { coverage, accuracy, status, last_studied, … },   // 기본이론
      deep:  { … },                                             // 심화이론
      prac:  { … },                                             // 문제풀이
      mock:  { … },                                             // 모의+핵심
    },
  } }
```

- **하위호환**: 기존 레코드는 `phases.basic` 으로 이관(마이그레이션 1회).
- `status` 판정(coverage ≥ 0.95 & accuracy ≥ 0.8 → `mastered`)은 **회독별로 독립 수행**.
- 영향 파일: `aiLearningStore.js`(저장·판정), `leafStats.js`(집계), 실력 리포트 `proficiency.js`, 현황 탭.

## 4. 단계별 매핑 축이 다르다 (중요)

전 단계를 관(leaf)에 붙이려 하면 문제풀이 249h + 모의 117h가 엉킨다.

| 단계 | 매핑 축 | 산출물 |
|---|---|---|
| 입문·기초·기본·심화 (572h) | **관(leaf)** | `notes/{unit_code}.{phase}.md` |
| 문제풀이 (249h) | **기출 문항 ID** | `by-question/{qid}.json` |
| 모의+핵심 (117h) | **회차 + 문항** | `by-question/` 동일 형식 |
| 특강 (44h) | **과목 전체 요약** | `notes/_final.md` |

문제풀이 강의를 `questions_db.json` 문항에 붙이는 것이 **가장 값어치 있는 산출물**이다 —
문제를 틀리면 "이 문제 강사 해설 듣기(12강 23:10)"가 바로 뜬다.

### ⑥ 매핑의 1순위 신호 — 강의자료 PDF (실측으로 확인)

**강의 화면에 띄우는 문서의 원본이 드라이브에 있고, 텍스트 레이어가 살아 있다.**

`1차_경제학/손병익/[2026_기본이론] …/강의자료/경제학+필기+노트/경제학 필기 노트_10판.pdf` (229쪽)
→ 키프레임 `057m38s`(2강)에 찍힌 화면과 **PDF 6쪽이 정확히 일치**
(`<4> 개별수요곡선과 시장수요곡선`, `<5> 수요량의 변화와 수요의 변화`, 푸터 `손병익 회계사 6`)

따라서 매핑은 이렇게 쌓는다:

| 층 | 출처 | 역할 |
|---|---|---|
| 1 | **필기노트 PDF 텍스트** | 골격. 쪽마다 무슨 논점인지 정확히 안다 |
| 2 | 카탈로그 `note_pages` | 강의 ↔ 필기노트 쪽 범위 연결 (경제 기본이론 49/53강 보유) |
| 3 | 전사본 | 그 쪽에서 강사가 **실제로 한 설명** |
| 4 | 키프레임 판서 | 그 쪽에 강사가 **손으로 더한 것** |

> ⚠️ **필기노트 쪽 번호는 PDF 인덱스가 아니다.** 한 PDF에 미시(PDF 1~126)와 거시(PDF 127~229)가
> 이어 붙어 있고 거시 시작점에서 **꼬리말 번호가 1로 리셋**된다. 강의 파일명의 "필기 p.14"는
> 꼬리말 번호를 가리키므로, PDF 인덱스로 착각하면 거시 강의 15강이 통째로 미시 쪽에 붙는다.
> (처음에 실제로 그렇게 나왔다 — 관 커버리지가 50개에서 멈췄고, 고친 뒤 97개가 됐다.)
> 해결: 꼬리말 `손병익 회계사 N`을 파싱해 (구역, 번호)로 들고 다니고, 후보를 두 구역에서
> 모두 뽑아 내용 유사도가 가르게 한다.

- 필기노트 쪽 ↔ 관(leaf) 매칭은 **텍스트 대 텍스트**라 전사본 의미분석보다 훨씬 정확하다.
- ⚠️ 화면 여백의 숫자(62·65·69)는 **손병익 본교재 참조번호**인데 그 교재는 드라이브에 없다.
  절대 좌표로 쓸 수 없고, 구간 경계·순서 신호로만 쓴다.
- ⚠️ `교재/미시경제학 마인드.pdf`(160쪽)는 **스캔본이라 텍스트 레이어가 없다**. 앱의 경제학 교재
  (`units/*.md`)는 마인드 기반이지만 강의 화면 문서와는 다른 책이다.

**다른 과목의 강의자료 보유 현황**

| 과목 | 강의자료 | 매핑 사다리 |
|---|---|---|
| 경제학 | 필기노트 **229쪽(텍스트○)** | 필기 쪽 → 관 ✅ |
| 민법 | 김동진 판서노트, 입문특강 자료 3회분 | 미확인 |
| 부동산학원론 | 빵구노트 43쪽 · 수업자료 1~2쪽 · 본교재(이종호 400쪽)는 **스캔본** | **없음** → 아래 대안 |
| 회계학 | 실전모의고사만 | **없음** |
| 감관법 | **없음** | **없음** |

### 사다리가 없는 과목의 대안 — 파일명 편·장 + 내용 매칭

`scripts/lectures/align_transcript_direct.py`

부동산학원론은 강의 파일명에 **편·장이 그대로** 있고 taxonomy와 번호가 일치한다.

## 8. 비용·시간 — 실측 (2026-08-10, M1 Pro / 16GB)

경제학 기본이론 **53강 47.9시간 완주** 기준.

| 작업 | 실측 | 1차 전체(965h) 환산 |
|---|---|---|
| 오디오 추출 (16kHz mono FLAC) | 60분 강의 → **7초**, 116MB | 약 **2시간**, **110GB** |
| 로컬 Whisper 전사 (large-v3-turbo) | 47.9h → **2.2h** = **평균 21.7배속** | 약 **44시간** 연속 가동 |
| 전사 텍스트량 | 53강 **124.8만 자** (강의당 23,556자) | 약 **2,500만 자** |

- 첫 강만 10.6배속이었고(모델 적재·워밍업) 이후 계속 **22배속**을 유지했다.
  초기 추정 91시간 → 실제 약 **44시간**으로 절반이 줄었다.
- 전사 품질: 한국어 구어체·도메인 용어 모두 양호. 고유명사·유사음 일부 오인식
  ("박문각"→"박문강", "생산가능곡선"→"생산가는 곡선", "기울기"→"기율") — ⑦ 압축 단계에서 교정 가능.
- 과목별 전사 소요(22배속 기준): 경제학 166h → **7.6h**, 회계학 314h → 14.5h,
  민법 175h → 8.1h, 감관법 176h → 8.1h, 부동산 135h → 6.2h.
- ⚠️ 오디오 용량이 초기 추정(35GB)보다 크다 → **110GB**. 외장 여유 2.8TB이므로 문제 없음.

| 처리 속도 | 53강(48시간) → **48분** · 강의당 평균 54초 |
| 프레임 수 | **1,446장** · 강의당 평균 **27장** (필터 전 74장 → 63% 감축) |
| 용량 | 평균 60KB/장 · 전체 **89MB** |
| 1차 전체 1,093강 환산 | 약 **2.9만 장** · 약 1.8GB · 처리 약 **17시간** |
| VLM 입력량 | 파일럿 약 190만 토큰 / 1차 전체 약 3,800만 토큰 |

> ⚠️ **exFAT 클러스터 낭비**: 실제 데이터 89MB가 디스크에는 **3.0GB**로 잡힌다
> (60KB 파일이 2MB 클러스터를 하나씩 차지). 1차 전체로는 실데이터 1.8GB → 할당 약 59GB.
> 여유 2.7TB라 당장 문제는 없지만, 신경 쓰이면 강의별로 tar 묶음으로 보관하면 사라진다.

## 8-1. 화면 구조와 키프레임 전략 (실측)

강의 화면 = **교재 PDF 스크롤 + 색깔 손글씨 판서**, 오른쪽 약 25%가 강사(크롭으로 제외).

**교재 페이지 번호가 화면에 그대로 찍힌다.** 파일명 힌트는 강의당 페이지 *범위*만 주지만
화면 번호는 **시각 단위로 정확한 페이지**를 준다 → ⑥ 관 매핑의 1순위 신호.

판서는 누적되므로 **페이지가 넘어가기 직전 프레임이 완성본**이다.
장면 전환 시각을 찾은 뒤 1.2초 뒤로 물러나 뜬다(전환 순간을 뜨면 이미 지워진 빈 페이지가 찍힌다).

| 프레임 유형 | 비중(체감) | 값어치 | 판단 |
|---|---|---|---|
| 교재 표·그래프 + 완성 판서 | 약 1/2 | **높음** | 표 빈칸에 채운 답, 수식·그래프 — 음성에 없는 정보 |
| 화이트보드 낙서 | 약 1/3 | 낮음 | 흘림 한글 판독難 + 내용은 음성이 이미 담음 |
| 스크롤 도중 | 나머지 | 없음 | 병합 필터로 제거 |

→ **판서 판독은 교재 페이지가 보이는 프레임에만** 걸고, 페이지 번호 판독은 값이 크고 싸므로 전체에 적용한다.

파라미터(실측 확정): `SCENE_TH=0.06`, `CLUSTER_SEC=3`, `MERGE_SEC=25`, `BACKOFF_SEC=1.2`, `CROP=1440:810:0:0`

### 설치된 도구
- `ffmpeg` 8.1.2 (homebrew)
- `mlx-whisper` — venv `~/.venvs/lecture-whisper` (Python 3.12), 모델 `mlx-community/whisper-large-v3-turbo`
- 작업 산출물 루트: `/Volumes/WD_Black/인터넷강의/_ai_pipeline/{audio,transcripts}/{subject}/`
