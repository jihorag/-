# 문항 등급 체계 A/B/C — 설계

작성 2026-08-28 · 대상 저장소 `감정평가사 기출문제` · 파일럿 과목 경제학원론

## 1. 배경

연습문제 DB가 품질이 전혀 다른 두 세대로 섞여 있고, 감정평가사 시험 수준에
맞는지 판정할 기준이 없다. 현재 앱은 `App.jsx:2704`에서 런타임 휴리스틱
(`option_meta` 보유 + 본문 앞 60자 중복 아님)으로 저품질을 걸러내는데, 이
규칙이 경제학 12,120문항 중 **9,886문항을 문제풀이 탭에서 제외**한다.

휴리스틱의 문제는 세 가지다. 판정 근거가 남지 않고, `option_meta`라는 형식
요소가 실제 품질을 대리하지 못하며, 난이도를 전혀 구분하지 않는다.

이 설계는 그 휴리스틱을 **데이터에 저장된 근거 있는 등급**으로 승격하고,
문항을 난이도 축으로 A/B/C 세 탭으로 나눈다.

## 2. 목표 / 비목표

**목표**
- 감평 시험 대비라는 목적에 맞는 문항만 남기는 품질 기준을 정의한다
- 남은 문항을 A(연습) / B(실전)로 나누는 난이도 기준을 정의한다
- 기출을 C로 두어 A → B → C 학습 동선을 만든다
- 판정 근거를 문항마다 기록해 나중에 재검토·되돌리기가 가능하게 한다

**비목표**
- 기출문제(C)는 선별하지 않는다. 13개 시험 1,834문항(경제) 전량 유지한다
- 단원별 정원(quota)을 두지 않는다. 기준을 통과하면 몇 개든 남긴다
- 이번 단계에서 신규 출제는 하지 않는다

## 3. 근거 데이터

경제학 기준 현황이다.

| 구분 | 문항 수 | 특징 |
|---|---|---|
| v1 자동생성 | 9,880 | 정답 1·2번에 88% 편중, 본문 평균 365자, 중복 1,383 |
| v2 수제(hq) | 2,240 | 정답 완전 균등, 본문 88자, `option_meta` 보유 |
| 기출(C 후보) | 1,834 | 13개 시험, 2009~2026 |

기출 5개 시험의 지표를 비교해 정량 지표의 분리력을 검증했다.

| 지표 | 공무원 | 노무사 | 감평 | 보계 | 회계사 | 판정 |
|---|---|---|---|---|---|---|
| 수식 포함률 | 48% | 60% | 65% | 73% | 72% | 난이도와 단조 상관 |
| 선지 평균길이 | 20.1 | 20.5 | 17.4 | 17.8 | 10.1 | 어려울수록 짧아짐 |
| 본문 중앙길이 | 116 | 111 | 124 | 125 | 203 | 회계사만 이탈 |
| 숫자 밀도 | 7.5 | 4.6 | 5.9 | 7.7 | 9.2 | 비단조, 사용 불가 |
| 단서(`단,`) | 34% | 42% | 52% | 42% | 47% | 감평 스타일 지표 |
| 보기결합(ㄱㄴㄷ) | 5% | 16% | 17% | 4% | 0% | 감평 스타일 지표 |

**결론**: 정량 지표는 집단 프로파일은 갈라내지만 개별 문항의 A/B 판정은
못 한다. 감평(65%)과 보험계리사(73%)가 거의 겹친다. 따라서 정량은 품질
게이트와 사후 검증에 쓰고, A/B 판정은 기출을 앵커로 붙인 LLM이 맡는다.

`단,`과 ㄱㄴㄷ는 난이도가 아니라 감평 고유 출제 스타일이므로 난이도 점수에
넣지 않고 별도의 스타일 축으로만 참고한다.

## 4. 등급 정의

| 등급 | 이름 | 정의 | 출처 |
|---|---|---|---|
| A | 연습문제 | 기출보다 쉽거나 개념 형성용 | 연습문제 DB 중 품질 통과분 |
| B | 실전문제 | 기출과 비슷하거나 더 어려움 | 연습문제 DB 중 품질 통과분 |
| C | 기출문제 | 실제 출제된 문항 | `questions_db.json` 전량 |
| — | 폐기 | 품질 게이트 탈락 | 물리 삭제하지 않고 라벨만 부여 |

C는 판정 대상이 아니다. `questions_db.json`의 문항은 무조건 C다.

## 5. 품질 게이트

다섯 항목을 모두 통과해야 A/B 후보가 된다. 하나라도 걸리면 난이도와 무관하게
폐기하거나 교정 대상으로 보낸다.

1. **정답 유일성** — 복수정답·무정답이 없다
2. **개념·계산 정확성** — 해설의 계산이 실제로 맞고 개념 서술에 오류가 없다
3. **해설 완결성** — 왜 정답인지와 왜 오답인지가 모두 있다
4. **비중복** — 같은 지식 포인트를 반복하지 않는다
5. **출제 범위 적합** — 감평 1차 경제학원론 범위 안이다

## 6. 난이도 기준

품질을 통과한 문항만 A/B로 나눈다.

**A 연습문제**
- 단일 개념만 묻는다
- 정의 확인 또는 1단계 계산
- 함정이 없고 오답이 명백히 다른 개념이다

**B 실전문제**
- 2개 이상 개념이 결합되거나 계산이 2단계 이상이다
- 오답이 매력적이다. 흔한 오개념이나 계산 실수 지점을 찌른다
- 감평 스타일 요소(`단,` 조건 명시, ㄱㄴㄷ 보기결합)를 갖추면 가산한다

경계에 걸리면 A로 내린다. B 탭의 신뢰도가 이 체계의 핵심이므로, 애매한
문항이 B에 섞이는 쪽이 A에 섞이는 쪽보다 손해가 크다.

## 7. 판정 파이프라인

**1단계 — 정량 품질 게이트 (전량, 무료)**

기출 분포에서 뽑은 임계로 명백한 불량을 거른다. 중복군은 전량 버리지 않고
**대표 1개를 살린다**. 경제학 실측 결과 12,120 → 7,704 생존이다.

| 규칙 | 임계 | 탈락 수 |
|---|---|---|
| 본문 장문 | 기출 P90 = 252자 초과 | 2,817 |
| 본문 중복 | 동일 본문 2회 이상, 대표 1개 제외 | 1,229 |
| 해설 부실 | 80자 미만 | 370 |
| 선지 수 | 5개 아님 | 0 |

중복 본문은 162종이며 대표 1개씩 총 162문항이 생존한다.

**2단계 — 기계 교정 (전량, 무료)**

문항을 손상시키지 않고 고칠 수 있는 결함만 처리한다.

- **정답 순서 편향** — 선지를 셔플하고 `answer`·`option_meta`를 재계산한다.
  1단계 생존분의 정답이 여전히 1번에 크게 몰려 있어 반드시 필요하다.
  셔플 후 단원별 정답 분포가 균등한지 확인한다

**3단계 — LLM 앵커 판정 (1·2단계 생존분 7,704)**

문항마다 같은 단원의 감평 기출 2~3문항을 앵커로 붙여 심사한다. 앵커가
있어야 LLM의 "어렵다"가 감평 시험 기준에 고정된다. 해당 단원에 감평 기출이
없으면 인접 단원 기출 또는 노무사 기출을 앵커로 쓰고, 그 사실을 기록한다.

출력은 `A` / `B` / `discard` / `repair` 넷 중 하나이며 사유를 함께 남긴다.

**4단계 — 선별 교정 (3단계가 `repair`로 보낸 것만)**

교정 트리거는 정원이 아니라 **탈락 사유**다.

| 사유 | 처분 |
|---|---|
| 장문 | LLM 압축 후 재심사 |
| 해설 부실 | LLM 보강 후 재심사 |
| 개념·계산 오류 | 즉시 폐기. 교정하지 않는다 |
| 범위 이탈 | 즉시 폐기 |

교정본은 3단계 심사를 다시 통과해야 A/B에 편입된다. 통과 못하면 폐기다.

**5단계 — 사후 검증**

A/B 집단의 수식 포함률과 선지 평균길이를 기출 프로파일과 대조한다. B 집단이
감평 기출(수식 65%, 선지 17.4자)에서 크게 벗어나면 3단계 임계를 조정하고
다시 돌린다.

## 8. 데이터 스키마

문항 최상위에 필드를 추가한다. `indexing_v4`는 분류 축이므로 건드리지 않는다.

```json
{
  "tier": "B",
  "tier_meta": {
    "decided_by": "claude-opus-5",
    "decided_at": "2026-08-28",
    "reason": "수요·공급 균형과 탄력성 두 개념 결합, 계산 2단계",
    "anchors": ["2019-감정평가사-경제학-14"],
    "anchor_fallback": false,
    "repaired": false
  }
}
```

- `tier` — `"A"` | `"B"` | `"C"` | `"discard"`
- 폐기는 **물리 삭제하지 않는다**. `tier: "discard"`로 두어 되돌릴 수 있게 한다
- `tier_meta.reason`은 필수다. 근거 없는 판정은 나중에 재검토가 불가능하다

## 9. 앱 연결

`viewer/src/App.jsx` 세 곳만 바뀐다.

1. **`:2704` 런타임 `lowq` 계산 제거** — 저장된 `tier`를 읽는다.
   `lowq`는 `tier === 'discard'`로 대체한다. `:6471`, `:6479`의
   드릴 연동은 그대로 동작한다
2. **`:2763` `baseFilter`** — 기존 `sourceFilter`(`all`/`official`/`practice`)를
   `tierFilter`(`all`/`A`/`B`/`C`)로 확장한다
3. **`:4941` 토글 UI** — 버튼 3개를 `전체 / A 연습 / B 실전 / C 기출` 4개로 바꾼다

`tier`는 문항 객체의 필드이므로 `sync-data.mjs`가 그대로 실어 나른다. 동기화
스크립트는 수정할 필요가 없다.

## 10. 함께 고치는 것

v2 수제 문항 2,240개는 `indexing_v4.mapped_taxonomy.item`이 전부 빈
문자열이다. `App.jsx:3025`의 관 카드 필터가 `taxItemName === it.name`이라
**관 단위로 들어가면 최고 품질 문항이 하나도 안 나온다**. 등급을 붙여도 이
문제가 남으면 B 탭이 관 학습에서 비므로, 이번 작업에 절→관 매핑 보정을
포함한다.

같은 맥락의 데이터 오류도 함께 고친다.

- ID 중복 5건 (`practice-econ-macro-ch01-sec02-item02-001` 등)
- `difficulty: 60` 1건 (`practice-econ-intl-ch01-sec02-item03-044`)

## 11. 단계와 범위

경제학원론을 파일럿으로 끝내고 결과를 확인한 뒤 나머지 과목으로 넓힌다.
과목마다 기출 앵커의 양이 다르므로(경제 1,834 대 법규 소량) 파일럿 결과가
그대로 이전되지 않는다.

1. 경제학 12,120문항 파일럿
2. 사후 검증에서 B 집단 프로파일 확인
3. 사용자 표본 검토 — B에서 20문항을 뽑아 실제 기출 수준인지 확인
4. 나머지 7과목 확대

## 12. 되돌리기

- 폐기가 물리 삭제가 아니므로 `tier`를 지우면 원상 복구된다
- 2단계 선지 셔플은 문항을 변형하므로, 셔플 전 원본을
  `questions_db_econ.json.pre_shuffle`로 백업한다
- 앱 변경 3곳은 `tier` 필드가 없으면 기존 `lowq` 동작으로 폴백하게 두어,
  데이터와 코드를 따로 배포할 수 있게 한다

## 13. 구현 계획에서 정할 것

3단계 LLM 심사에 쓸 모델과 배치 크기. 대상은 7,704문항이다. 기본값은 문항
20개 묶음 배치이며, 판정 일관성을 먼저 표본으로 확인한 뒤 전량에 돌린다.
