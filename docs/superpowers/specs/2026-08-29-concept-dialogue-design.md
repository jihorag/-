# 개념 완성 2차 — 목차 호응 + 캐릭터 대화 학습

> 2026-08-29 설계. 과목: **경제학원론**.
> 1차 설계는 [2026-08-28-lecture-concept-track-design.md](2026-08-28-lecture-concept-track-design.md).
> 이 문서는 그 위에 **목차 정합**과 **대화형 학습**을 얹는다.

---

## 1. 목표와 성공 기준

**목표 둘.**

1. 개념 완성의 목차가 AI 학습의 목차와 **완전히 같아 보인다.** 같은 계층, 같은 순서, 빈칸 없음.
2. 학습이 **읽기가 아니라 대화**다. 캐릭터들과 주고받으며 배우고, 틀릴 수 있고, 틀리면 이유를 듣는다.

**성공 기준.**

- 개념 완성에서 어떤 관을 열어도 학습할 것이 있다. "아직 트랙이 없습니다"가 뜨는 관이 없다.
- 한 논점을 마치려면 **최소 한 번은 선택해야 한다.** "다음"만 눌러서는 통과할 수 없다.
- 틀린 선택마다 **그 선택에만 해당하는 반박**이 나온다. "오답입니다"가 아니라 "그건 수요 쪽 얘기예요"가 나온다.

세 번째가 이번 설계의 핵심이다. 오답이 채점이 아니라 **다음 대사를 부르는 분기**가 되는 것이 "재미"의 실체이고, 그것 없이는 캐릭터를 붙여도 여전히 읽기다.

## 2. 현재 상태 (실측, 2026-08-29)

### 2-1 목차가 어긋나 있다

| | |
|---|---:|
| taxonomy 관 | 221 |
| 트랙 있는 관 | 97 |
| 화면에 그려지는 목차 | **평면 목록 221개** |

두 가지 원인이 겹쳐 있다.

**(1) 개념 완성만 공유 목차 모델을 안 쓴다.** `viewer/src/unitTree.js` 첫 줄이 이렇다:

> AI학습·드릴·문제풀이 세 탭이 공유하는 '단일 목차' 모델

`ConceptTrack.jsx`는 이 모델을 쓰지 않고 `leaves` 배열을 그대로 나열한다. 세부과목→장→절→관 계층이 통째로 빠져 있다.

**(2) 커버리지 구멍 124관.** 대분류별 분포:

| 대분류 | 전체 | 트랙 있음 | 빠짐 |
|---|---:|---:|---:|
| 미시경제학 | 77 | 50 | 27 |
| 거시경제학 | 67 | 37 | 30 |
| 국제경제학 | 16 | 10 | 6 |
| 재정학 | 61 | 0 | **61** |

### 2-2 재정학은 강의가 없다

회독별로 "재정·조세·공공재·후생" 이 제목에 걸리는 강의 수:

| 회독 | 강의 | 재정학 관련 |
|---|---:|---:|
| 기본이론 | 53 | 4 (미시·거시 장 안의 조세·외부성·공공재) |
| 심화 | 47 | 3 |
| 문제풀이 | 56 | 1 |
| 모의·특강 | 62 | 0 |

**어느 회독에도 재정학 단원이 없다.** 강사의 경제학원론 강의는 미시·거시·국제만 다루고, taxonomy 의 재정학 61관은 교재에만 있는 범위다. 심화 강의는 1~20장, 기본이론은 1~23장을 다뤄 **심화가 오히려 좁다** — 심화를 전사해도 새 관이 열리지 않고 기존 관이 깊어질 뿐이다.

### 2-3 나머지 63관은 강의 부재가 아니라 정렬 구멍이다

재정학을 뺀 160관 범위에서, 절(節) 단위로 세면:

| 절 상태 | 개수 |
|---|---:|
| 그 절의 관 전부에 트랙 있음 | 5 |
| **일부 관에만 있음** | **39** |
| 절 전체가 빔 | 3 (7관) |

**39개 절이 "강의는 그 절을 다뤘는데 일부 관에만 붙었다"** 상태다. 실제 사례가 `--check` 에 잡혀 있다 — 「제2관 수요의 소득탄력성·교차탄력성」이 3강 40.9분을 통째로 받았고 그 안에 **가격탄력성 논점이 6개** 들어 있는데, 정작 같은 절의 「제1관 수요의 가격탄력성」은 트랙이 없다. 내용은 존재하는데 엉뚱한 관에 실렸다.

즉 이 63관은 **새 전사 없이 회수할 수 있다.**

### 2-4 지금 논점은 읽기다

실제 논점(`M02` 제4관 첫 논점):

> **body (358자 중앙값)** — "공급자는 시장 가격이 상승할 때 더 많은 물량을 판매하고자 하는 유인을 가진다. 이러한 경제적 동기에 따라 가격이 오르면 공급량이 증가하며…"
> **check** — "가격이 상승할 때 공급량이 증가하는 현상을 무엇이라고 하는가?" → "공급의 법칙."

비유도 예시도 되물음도 없다. 그럴 수밖에 없는 것이, 생성 프롬프트가 **"교재처럼 단정 서술하라, 강사·강의라는 단어를 쓰지 말라"** 를 강제한다. 교재 *보충*용으로 설계된 문체를 그대로 물려받았다.

그런데 같은 앱의 `aiClaudeClient.js` `SYSTEM_RULES` 는 정반대를 지시한다:

> ① 일상 언어로 먼저 풀어 설명 — 처음 듣는 친구에게 카페에서 말하듯 ② 한자/어원 분해 ③ 실생활 비유 ④ **그 다음에 비로소** 교재의 정확한 표현 ⑤ 아주 쉬운 확인 질문

**개념 완성이 물려받아야 할 목소리는 이쪽이다.** 시각자료도 763논점 중 148개(19%)뿐이다.

### 2-5 이미 있는 재료

- `viewer/src/unitTree.js` — `buildUnitTree(leaves)` → 세부과목/장/절/관 트리 + 서수.
- `viewer/src/ParsedText.jsx:244-252` — **이모지로 구분되는 콜아웃 블록.** `🐶` 는 이미 "복습 메이트(마스코트)"로 등록돼 있고, 주석에 "다른 콜아웃과 성격이 다르므로 유일하게 푸른 계열을 쓰되 채도는 낮게 둔다"고 적혀 있다. 캐릭터를 얹을 자리가 이미 있다.
- `viewer/src/Speech.jsx` — Web Speech API TTS. 외부 의존성 0.
- `viewer/src/viz/` — 템플릿 18개 + 단계 재생(`steps`).
- `viewer/src/trackProgress.js` — 논점 진도. **이번 설계에서 바뀌지 않는다.**

## 3. 설계 개요

```
[A] 목차 호응
    ① ConceptTrack 이 buildUnitTree 를 쓴다        (코드)
    ② 재정학을 개념 완성 범위에서 제외한다            (코드)
    ③ 절 안에서 관별로 구간을 다시 나눈다             (파이프라인) → 63관 회수
    ④ 그래도 안 붙는 7관만 교재로 만든다              (파이프라인)

[B] 대화형 학습
    ⑤ 논점 스키마를 body → turns 로 넓힌다           (스키마)
    ⑥ 캐릭터 넷이 각자 학습 단계를 맡는다              (프롬프트)
    ⑦ 선택지와 오답별 반박을 넣는다                   (스키마 + 화면)
    ⑧ 대사·선택지는 사전 생성, 꼬리질문만 실시간        (파이프라인)
```

## 4. 목차 호응

### 4-1 `buildUnitTree` 재사용

`ConceptTrack.jsx` 의 `LeafList` 를 트리 렌더로 바꾼다. `AILearning` 이 쓰는 것과 **같은 함수, 같은 입력**이므로 순서와 계층이 자동으로 일치한다. 새 목차 모델을 만들지 않는다.

각 노드에 **남은 논점 수**를 함께 표시한다. 스펙 §1 의 "남은 논점이 몇 개인지 보인다"가 지금은 관 안에 들어가야만 보이는데, 목차에서 바로 보이게 한다.

목차가 읽을 진도 요약은 생성 시점에 만든 색인에서 온다:

```
viewer/public/data/study/{과목}/lectures/track/_index.json
{ "leaf_id": { "points": 8, "source": "lecture" }, … }
```

트랙 파일 18개를 전부 fetch 하지 않고 이 한 파일만 읽는다.

### 4-2 재정학 제외

개념 완성의 목차 범위에서 `path[0] === '재정학'` 인 관을 뺀다. 160관이 된다.

**taxonomy 자체는 건드리지 않는다.** AI 학습·드릴·문제풀이는 지금처럼 재정학을 포함한다 — 그 탭들은 교재 기반이라 강의가 없어도 성립한다. 제외는 개념 완성 화면에서만 한다.

제외 규칙은 데이터로 둔다:

```
viewer/public/data/study/{과목}/lectures/scope.json
{ "exclude_divisions": ["재정학"], "reason": "강의 없음 — 어느 회독에도 재정학 단원이 없다" }
```

코드에 과목명을 박지 않는다. 다른 과목으로 넓힐 때 파일만 추가한다.

### 4-3 절 안에서 관별로 다시 나누기 (63관 회수)

**문제:** `align_transcript_direct.py` 와 경제학의 필기노트 사다리 방식 둘 다 절 수준까지는 잘 맞지만, 한 절 안에서 관을 가르지 못해 절의 전 구간이 한 관에 몰린다.

**해법:** 정렬 뒤에 **2차 분배** 단계를 넣는다. 새 스크립트 `scripts/lectures/split_spans_by_item.py`.

절마다:

1. 그 절에 속한 관 목록과, 각 관의 교재 슬라이스(제목 + 소제목 목록)를 모은다.
2. 그 절에 붙은 spans 를 시각 순으로 놓는다.
3. spans 를 관에 **단조 배정**한다 — 강의는 교재 순서대로 진행하므로 뒤로 돌아가지 않는다. `map_notes_to_leaves.monotonic_assign` 이 이미 이 일을 한다. 재사용한다.
4. 유사도는 `tfidf_vectors` + `cosine` — 같은 모듈에 있다.

**절 전체가 한 관에 몰려 있던 경우에만** 재분배한다. 이미 여러 관에 잘 나뉜 절은 건드리지 않는다.

산출은 `align.json` 을 덮어쓰지 않고 `align_split.json` 으로 따로 쓴다. 생성기가 있으면 그걸 쓰고 없으면 기존 것을 쓴다. **되돌릴 수 있어야 한다** — 2차 분배가 오히려 나쁘면 파일만 지우면 된다.

**검증:** 분배 전후로 ① 관 커버리지가 몇 개 늘었는지 ② 총 spans 수가 보존되는지(유실 0) ③ 표본 관의 논점 제목이 관 제목과 맞는지.

### 4-4 남는 7관은 교재로

절 전체가 비어 있는 3개 절 7관은 강의가 실제로 안 다룬 것으로 본다:

- 거시경제학 / 제1장 / 제1절 거시경제학의 기초 (2관)
- 거시경제학 / 제6장 / 제15절 각 학파 모형의 주요내용 (3관)
- 미시경제학 / 제1장 / 제2절 경제학의 방법론 (2관)

이 관들은 교재 본문(`section_lines`)만으로 논점을 만든다. 논점마다 `source: "textbook"` 을 남기고 화면에도 구분해 보인다 — 강의 기반이 더 생생하므로 학습자가 알아야 한다.

2차 분배 결과에 따라 이 목록은 달라질 수 있다. **하드코딩하지 않고** 분배 뒤에 남은 관을 계산해서 만든다.

## 5. 논점 → 대화 세션

### 5-1 스키마

기존 필드는 그대로 두고 `turns` 를 더한다. **`body` 를 지우지 않는다** — 763논점이 이미 있고, `turns` 가 없으면 화면이 `body` 로 폴백한다. 재생성을 관 단위로 점진적으로 할 수 있다.

```json
{
  "seq": 5,
  "id": "M02-L04-p05",
  "title": "수요가 늘면 균형은 어디로 가는가",
  "gist": "한 줄 요약",
  "source": "lecture",
  "body": "기존 교재체 서술 — turns 가 있으면 화면에 안 쓰고 근거로만 남긴다",
  "turns": [
    { "who": "ask",   "text": "이거 왜 배워요?" },
    { "who": "teach", "text": "쉽게 말하면 …",
      "viz": { "template": "supply-demand", "params": {}, "steps": [] } },
    { "who": "quiz",
      "prompt": "가격이 오르면 공급량은 어떻게 될까요?",
      "choices": [
        { "text": "늘어난다", "ok": true,
          "reply": "맞아요. 파는 쪽은 값이 오르면 더 팔고 싶어지니까요." },
        { "text": "줄어든다", "ok": false, "who": "gotcha",
          "reply": "그건 사는 쪽 얘기예요. 파는 사람 입장에서 생각해봐요 — 값이 비싸지면 더 팔고 싶겠죠?" },
        { "text": "변하지 않는다", "ok": false, "who": "gotcha",
          "reply": "그러면 공급곡선이 수직이라는 뜻인데, 그건 아주 특수한 경우예요." }
      ] },
    { "who": "teach", "text": "교재 표현으로는 '공급의 법칙'이라고 합니다. …" },
    { "who": "gotcha", "text": "그런데 '공급량 변화'와 '공급 변화'는 다릅니다. 시험은 여기를 찌릅니다." },
    { "who": "mate",  "text": "이 절에서 외울 건 곡선 위 이동과 곡선 자체 이동의 구분 하나입니다." }
  ],
  "example": {
    "q": "예시 문제 본문",
    "solution": "풀이 — 접어 두었다가 펼친다"
  },
  "check": { "q": "…", "a": "…" },
  "src": [ { "lec": 7, "t": 600 } ]
}
```

**규칙**

- `turns` 는 6~12개. 그보다 짧으면 대화가 아니고, 길면 한 논점이 너무 크다.
- **`quiz` 턴이 최소 하나 있어야 한다.** 없으면 "다음"만 눌러 통과할 수 있고, 그러면 §1 의 성공 기준이 깨진다.
- 오답 `choice` 에는 **그 오답 전용 `reply`** 가 있어야 한다. "틀렸습니다" 같은 일반 문구는 금지.
- `viz` 는 `teach` 턴에만 붙는다. 기존 viz 스키마·단계 재생을 그대로 쓴다.
- `example` 은 선택. 계산·판단이 있는 논점에만.
- `check` 는 남긴다 — 복습·드릴에서 재사용할 여지가 있고 비용이 거의 없다.

### 5-2 캐릭터

넷이고, 각자 학습 사이클의 한 단계를 맡는다. 이 넷인 이유는 **시험 문제가 만들어지는 방식과 같기** 때문이다 — 개념이 열리고, 세워지고, 함정으로 비틀리고, 전략이 붙는다.

| `who` | 이름 | 이모지 | 역할 | 말투 |
|---|---|---|---|---|
| `ask` | 묻는 이 | 🙋 | 학습자 대신 묻는다 | 짧고 솔직하게. "이거 왜 배워요?" "아까 그거랑 뭐가 달라요?" |
| `teach` | 선생 | 📖 | 설명한다 | 일상 언어 → 비유 → 그 다음에 교재 표현 |
| `gotcha` | 깐깐이 | 🔍 | 찌른다 | 반례·경계조건·시험 함정. "그럼 이 경우엔요?" |
| `mate` | 복습 메이트 | 🐶 | 조언한다 | 무엇을 외우고 무엇은 넘길지. **내용 설명 금지** — 기존 규칙 그대로 |

`🐶` 는 이미 `ParsedText` 에 등록돼 있다. 나머지 셋을 같은 방식으로 등록한다.

**표현은 무채색이다.** 이 저장소의 UI 는 회색조를 쓰고 컬러를 자제한다(반복 확인된 선호). 캐릭터를 색으로 구분하지 않는다:

- 단색 이모지 + 이름
- 저채도 바 — `🐶` 가 쓰는 `#7c8db5` 계열 하나만 유지하고 나머지는 회색조 (`#6b7280`, `#94a3b8`, `#a3a3a3`)
- 화자 구분은 **말풍선 좌우 위치**로 한다. `ask` 는 오른쪽(학습자 편), 나머지는 왼쪽.
- 아바타 일러스트를 만들지 않는다.

### 5-3 화면 흐름

```
┌ 진도  ●●●●●○○○○  5 / 9 ───────────────┐
│  5. 수요가 늘면 균형은 어디로 가는가       │
│                                        │
│  🙋 묻는 이                              │
│     이거 왜 배워요?                       │
│                                        │
│  📖 선생                                 │
│     쉽게 말하면 …                         │
│     [ 그림 · 단계 재생 ◀ ▶ ]              │
│                                        │
│  📖 선생                                 │
│     가격이 오르면 공급량은?                │
│     ┌──────────┬──────────┬──────────┐  │
│     │ 늘어난다  │ 줄어든다  │ 안 변한다 │  │
│     └──────────┴──────────┴──────────┘  │
│                                        │
│              [ 🔊 ]   [ 💬 더 묻기 ]     │
└────────────────────────────────────────┘
```

- 턴은 **한 번에 하나씩** 열린다. 화면을 채워 놓고 스크롤하게 두지 않는다.
- `quiz` 턴에서는 **고르기 전에는 다음으로 못 간다.**
- 오답을 고르면 그 오답의 `reply` 가 깐깐이 말풍선으로 붙고, 다시 고를 수 있다. **정답을 맞힐 때까지 진행하지 않는다** — 다만 두 번 틀리면 정답을 알려주고 넘어간다(막히면 학습이 멈춘다).
- 논점 통과 판정: **`quiz` 를 맞혔을 때** `PASSED`. 지금의 "이해했어요" 자기 신고를 대체한다. `trackProgress.js` 는 안 바뀐다 — 부르는 시점만 바뀐다.
- TTS(`Speech.jsx`)를 말풍선마다 붙인다. 캐릭터별로 다른 음성을 쓸 수 있으면 쓰고, 브라우저가 한국어 음성을 하나만 주면 그냥 하나로 간다.
- 「더 묻기」는 그 논점의 `turns` 를 system 블록에 실어 기존 대화 엔진을 부른다. (1차 설계 §6-3 의 미구현분을 여기서 해결한다.)

## 6. 생성 파이프라인

`scripts/lectures/build_topic_track.py` 의 프롬프트를 바꾼다. 스크립트 구조(증분 저장, 건너뛰기, `--force`, viz 카탈로그 과목 필터, 전사 무손실 분할, 이스케이프 복구)는 **그대로 쓴다.**

### 6-1 문체를 뒤집는다

지금 프롬프트의 이 지시를 **`turns` 에 한해 해제한다**:

> "교재처럼 단정 서술하세요" / "일상 언어로 풀지 마세요"

대신 `aiClaudeClient.js` 의 `SYSTEM_RULES` 가 쓰는 순서를 그대로 요구한다 — 일상 언어 → 어원 → 비유 → 교재 표현 → 확인.

**유지되는 것:**

- "강사·강의·선생님" 이라는 **단어**는 여전히 금지한다. 캐릭터 「선생」이 말하는 것이지 강사를 인용하는 게 아니다.
- 전사에 없는 결론·수치·예시를 지어내지 않는다(1차 설계에서 실제로 발생한 사고).
- 전사가 결론 전에 끊기면 채우지 않는다.
- 대칭 구조는 축마다 독립 논점.

### 6-2 오답 선택지를 어떻게 만들게 할 것인가

프롬프트에 명시한다:

- 오답은 **그럴듯해야** 한다. 학습자가 실제로 헷갈리는 것 — 반대 개념(수요 vs 공급), 조건 하나 바꾼 것, 방향만 뒤집은 것.
- 각 오답의 `reply` 는 **왜 그렇게 생각했는지 짚고** 바로잡는다. "틀렸습니다"로 시작하지 않는다.
- 전사에서 강의가 실제로 경고한 함정이 있으면 그걸 오답으로 쓴다.

### 6-3 비용

1차 생성은 97관 · 출력 37만 토큰이었다. `turns` 는 논점당 출력이 3~5배다.

160관 기준 **입력 300만대 / 출력 150만~250만 토큰, 3~5시간** 으로 본다. 관 단위 증분 저장과 건너뛰기가 이미 있으므로 나눠 돌릴 수 있다.

기존 763논점의 `body` 는 프롬프트에 함께 넣어 재료로 쓴다 — 처음부터 다시 읽는 것보다 싸고, 이미 검증된 내용이다.

## 7. 진도와 coverage

**바뀌지 않는다.** `trackProgress.js` 의 `STATE`·`leafCoverage`·`nextPoint` 를 그대로 쓰고, `mastery.phases.basic.coverage` 도 그대로 논점 소진율이다.

바뀌는 것은 `PASSED` 를 찍는 시점 하나 — "이해했어요" 버튼에서 **`quiz` 정답** 으로. 자기 신고가 실제 판정으로 바뀌므로 coverage 의 신뢰도가 한 단계 더 올라간다.

## 8. 검증

`build_topic_track.py --check` 에 더한다:

1. 모든 논점에 `turns` 가 있는가(폴백 `body` 만 있는 관은 "미갱신"으로 보고).
2. `turns` 에 `quiz` 가 최소 하나 있는가. **없으면 그 논점은 통과 불가**이므로 문제다.
3. 각 `quiz` 에 정답이 정확히 하나, 오답이 둘 이상 있는가.
4. 모든 오답에 전용 `reply` 가 있는가. 빈 문자열이거나 "틀렸습니다" 류면 보고.
5. `who` 값이 넷 중 하나인가.
6. 목차 범위(`scope.json` 적용 후) 안에서 트랙이 없는 관 목록 — 0이어야 한다.

앱 쪽은 `node --test` 로:

- 턴 진행 상태 기계(다음 턴, 선택 판정, 두 번 틀리면 공개)를 순수 함수로 빼서 테스트한다. 화면과 분리한다.

## 9. 하지 않는 것

- **심화·문풀 전사** — §2-2 에서 확인한 대로 목차 빈칸을 못 채운다. 2회독 재료로는 가치가 있으나 이번 목적이 아니다.
- **재정학 논점 생성** — 강의가 없고, 사용자가 개념 완성에서 제외하기로 정했다.
- **캐릭터 아바타 일러스트** — 무채색 원칙과 충돌하고, 이모지 + 이름으로 충분하다.
- **실시간 대사 생성** — 사전 생성으로 간다. 「더 묻기」만 실시간.
- **다른 과목 확장** — 경제학에서 검증한 뒤.
- **`trackProgress.js` 변경** — 진도 모델은 이미 맞다.
