# 논점 트랙 — 인강을 듣지 않고 강의 내용을 전부 파악하는 시스템

> 2026-08-28 설계. 파일럿 과목: **경제학원론**.
> 기존 강의 파이프라인은 [강의-파이프라인-인수인계.md](../../강의-파이프라인-인수인계.md) 참조.

---

## 1. 목표와 성공 기준

**목표** — 인강 영상을 보지 않고도 그 강의가 다룬 내용을 빠짐없이 익힌다. 읽는 문서가 아니라 **대화와 시각자료로** 익힌다.

**성공 기준** — 관(關)마다 "이 강의가 실제로 다룬 논점"의 목록이 존재하고, 학습자가 그 목록을 하나씩 소진할 수 있으며, **남은 논점이 몇 개인지 화면에 보인다.** 목록을 다 비우면 그 관의 강의를 끝까지 들은 것과 동등하다.

이 판정 장치가 설계의 중심이다. 재료를 늘리는 것도 애니메이션을 붙이는 것도 그 다음이다. 진도를 셀 수 없으면 "다 파악했다"는 영원히 주관이다.

## 3. 설계 개요

```
[전사 + align.by_leaf + 교재 슬라이스 + 판서 키프레임]
        │  build_topic_track.py (배치, 사전 생성)
        ▼
  track/{유닛}.basic.json   ← 논점 트랙: 강의 진행 순서대로 나열된 논점 카드
        │  sync-data → 앱
        ▼
  「개념 완성」 화면 — 논점을 하나씩 대화로 소진, 진도바
        │
        ▼
  mastery.phases.basic.coverage = 소진 논점 ÷ 전체 논점  (실측값)
```

세 갈래로 나뉜다.

1. **재료** — 논점 트랙을 사전 생성한다 (§4, §5).
2. **주행** — 「개념 완성」 화면이 트랙을 소진한다 (§6, §7).
3. **표현** — 기존 viz 템플릿에 단계 재생을 얹는다 (§8).

## 4. 논점 트랙 — 데이터

### 4-1 위치

```
viewer/public/data/study/{과목}/lectures/track/{unit_code}.{phase}.json
예: viewer/public/data/study/economics/lectures/track/M01.basic.json
```

기존 `notes/{unit_code}.{phase}.md`와 같은 층위에 나란히 둔다. 유닛 하나에 여러 관이 들어가는 것도 `notes`와 동일하다.

### 4-2 스키마

```json
{
  "subject": "economics",
  "phase": "basic",
  "unit_code": "M01",
  "leaves": [
    {
      "leaf_id": "economics__미시경제학__제1장_경제학의_기초__제1절_경제학의_개요__제1관_경제학의_정의와_분류",
      "title": "제1관 경제학의 정의와 분류",
      "points": [
        {
          "seq": 1,
          "id": "M01-L01-p01",
          "title": "희소성이 경제학을 낳는다",
          "gist": "한 줄 요약 — 목록에서 보이는 문장",
          "body": "강의의 설명을 교재 문체로 옮긴 본문. 400~800자.",
          "viz": {
            "template": "supply-demand",
            "params": { "...": "..." },
            "steps": [ { "label": "최초 균형", "shifts": [] } ]
          },
          "check": { "q": "확인 질문 한 개", "a": "정답과 왜 그런지" },
          "src": [ { "lec": 2, "t": 600 }, { "lec": 2, "t": 720 } ]
        }
      ]
    }
  ],
  "orphans": [
    { "lec": 7, "t": 1320, "gist": "어느 관에도 붙지 않은 구간 요약" }
  ]
}
```

**필드 규칙**

- `seq` — **강의 진행 순서.** 이것이 "타임라인을 논점 단위로" 옮긴 축이다. 화면에는 순서만 보이고 시각은 보이지 않는다.
- `id` — 안정 식별자. 진도 저장의 키이므로 재생성해도 바뀌면 안 된다. `{unit}-L{leafIdx:02d}-p{seq:02d}` 규칙으로 만든다. 트랙을 다시 생성해 논점이 늘거나 줄면 id가 밀리므로, 재생성 시 §9-2의 마이그레이션을 거친다.
- `body` — 강의를 옮겨 적지 않는다. `generate_notes.py`의 기존 문체 규칙(강사·강의·선생님 금지, 큰따옴표 인용 금지, 교재처럼 단정 서술)을 그대로 상속한다. 저작권 축이 바뀌지 않는다.
- `viz` — 없어도 된다(`null`). 있으면 `template`은 `vizRegistry`에 등록된 이름이어야 한다.
- `check` — 논점당 정확히 하나. 완주 판정의 근거다.
- `src` — **내부 앵커. 화면에 노출하지 않는다.** 지금 `[43강 39:45]`가 `stripLectureCitations`로 지워지는 것과 동일하게 취급한다. 재생성·검증·디버깅 전용이다.
- `orphans` — 어느 관에도 매핑되지 않은 전사 구간. §5-3 참조.

### 4-4 관에 안 붙는 강의 — 과목 레벨 트랙

관 축에 매핑되지 않는 강의(§2-3의 4강)는 버리지 않고 `track/_subject.basic.json`에 담는다. 스키마는 §4-2와 같되 `leaves[].leaf_id`가 `null`이고 `title`이 강의 성격을 나타낸다.

```json
{ "subject":"economics", "phase":"basic", "unit_code":"_subject",
  "leaves":[
    { "leaf_id": null, "kind": "prereq", "title": "경제 기초수학",
      "points":[ … ] },
    { "leaf_id": null, "kind": "review", "title": "미시경제학 총정리",
      "points":[ … ] }
  ] }
```

- `kind: "prereq"` — 개념 완성 화면의 **맨 앞**에 놓는다. 본 과정 전에 훑는 선행이다.
- `kind: "review"` — **맨 뒤**에 놓는다. 전 관을 마친 뒤의 총정리다.
- 관에 안 붙으므로 `mastery` coverage에는 반영하지 않는다. 자체 진도만 센다.

### 4-3 분량 추정

경제학 97관 × 논점 10~25개 = 약 1,500 논점. 논점당 `body` 600자 + 부속 → 관당 1.2만자, 전체 약 120만자 ≈ 3MB. `notes/`(42만자)보다 크지만 저장소에 커밋해도 문제없는 규모다. 오디오·전사·키프레임은 지금처럼 외장에만 둔다.

## 5. 생성 — `scripts/lectures/build_topic_track.py`

기존 파이프라인 ⑤(align)와 ⑥(generate_notes) **사이**에 끼운다.

```bash
python3 scripts/lectures/build_topic_track.py economics --phase basic
python3 scripts/lectures/build_topic_track.py economics --phase basic --check
```

`generate_notes.py`와 같은 골격을 쓴다 — 같은 `_paths`, 같은 Gemini 호출, 같은 "이미 만든 것은 건너뛴다" 규칙, 같은 `SUBJECT_RULES`(숫자·조문 지어내기 금지).

### 5-1 관 하나를 만드는 절차

1. `align.json`의 `by_leaf[leaf_id]`에서 spans를 시각 순으로 정렬한다. **강좌(`course`)가 여럿이면 강좌별로 묶어 정렬한다** — 회계·법규에서 이미 겪은 함정이고, 트랙은 순서 자체가 산출물이라 여기서 틀리면 전부 틀린다.
2. spans의 전사 텍스트를 이어 붙인다. 관당 중앙값 16분, 최대 4시간이므로 **긴 관은 나눠 호출하고 논점 목록을 이어 붙인다.** `generate_notes.py`의 `MAX_TRANSCRIPT = 60000` 잘라내기 방식은 트랙에는 쓰지 않는다 — 잘라내면 뒤쪽 논점이 통째로 사라지고, 그게 정확히 이 프로젝트가 없애려는 손실이다.
3. 교재 슬라이스(`section_lines`)와 판서 키프레임(관당 최대 8장)을 같이 넣는다.
4. Gemini에게 요구한다: 강의가 **실제로 다룬 논점**을 진행 순서대로 나열하고, 각 논점에 `body`·`check`를 쓰고, 시각자료가 도움이 되면 `[VIZ_CATALOG]`에서 골라 파라미터를 채워라. 카탈로그 텍스트는 `vizRegistry.buildCatalog()`가 이미 생성하므로 그대로 재사용한다.
5. `src` 앵커는 각 논점이 나온 span의 `(lecture no, start)`로 채운다.

### 5-2 논점 개수 규율

한 관에 논점이 3개 미만이면 추출 실패를 의심하고, 40개를 넘으면 잘게 쪼갠 것을 의심한다. `--check`가 양 끝을 보고한다. 이건 상한을 강제하는 게 아니라 **눈에 띄게 만드는** 장치다.

### 5-3 커버리지 구멍이 저절로 드러난다

spans는 `align.json`이 관에 붙인 것만 있다. 어느 관에도 안 붙은 전사 구간은 트랙을 만들 때 자연히 남는다. 그걸 `orphans`에 요약과 함께 적어 두면:

- 민법 34관·회계 55관이 왜 비었는지가 처음으로 눈에 보인다.
- 경제학 4강 누락(§2-3)도 같은 경로로 잡힌다.

별도 감사 도구를 만들지 않는다. 트랙 생성의 부산물로 얻는다.

### 5-4 비용 추정

회계 140관 필기 생성이 입력 305만 / 출력 15만 토큰, 51분이었다. 트랙은 관당 출력이 3~4배 크다. 경제학 97관 기준 **입력 200만대 / 출력 50만대 토큰, 60~90분** 정도로 본다. 한 번 돌리면 끝이고, 이후에는 앱이 API 키 없이도 트랙을 읽는다.

## 6. 앱 — 「개념 완성」

### 6-1 화면 분리

| | 개념 완성 (신설) | AI 학습 (기존) |
|---|---|---|
| 모드 | `study` | `deep` `practice` `diagnose` `summary` |
| 회독 | 1회독 기본 | 2·3·4회독 + 특강 |
| 진행 | 논점 트랙 선형 주행 | 자유 대화 |

`MODE_TO_PHASE`가 이미 모드↔회독을 잇고 있으므로, **모드를 두 화면으로 갈라 놓기만 하면 진척·숙달도·강의 필기 주입이 자동으로 따라온다.** 새 저장 구조를 만들지 않는다.

### 6-2 네비게이션

현재 탭 6개이고 `App.jsx:3830`에 "모바일(sm)에서는 5개까지가 390px 한계"라고 적혀 있다. 탭을 7개로 늘리지 않는다. `tutor` 탭 아래에 **기존 `SUB_TABS` 패턴**(`plan`·`report`가 이미 쓰는 것)으로 `[개념 완성 | 심화]`를 붙인다.

```js
SUB_TABS = {
  plan:   [['planner','플래너'], ['curriculum','커리큘럼']],
  tutor:  [['concept','개념 완성'], ['civil','심화']],   // 신설
  report: [['proficiency','실력 리포트'], ['stories','합격수기']],
}
```

`TAB_HOME_VIEW.tutor`를 `'concept'`으로 바꾼다 — AI 학습 탭을 누르면 개념 완성이 먼저 열린다. 1회독이 먼저이므로 맞다.

### 6-3 한 논점의 화면

```
┌ 진도바  ●●●●●○○○○○  5 / 12 ────────────────┐
│                                             │
│  5. 수요가 늘면 균형은 어디로 가는가          │
│                                             │
│  [ 시각자료 — 단계 재생 ◀ ▶ ]                │
│                                             │
│  본문(body)…                                 │
│                                             │
│  ─ 확인 ─                                    │
│  Q. …                                        │
│  [답 입력]                    [모르겠어요]    │
│                                             │
│  💬 이 논점에 대해 더 묻기 →                  │
└─────────────────────────────────────────────┘
```

- `body`·`viz`·`check`는 **사전 생성분을 그대로 읽는다.** API 키 없이도 여기까지는 동작하고, 즉시 뜨고, 오프라인에서도 된다.
- **"더 묻기"를 누르면 기존 대화 엔진이 붙는다.** 그 논점의 `body` + 관 교재 슬라이스를 system 블록에 실어 기존 `sendMessages`를 호출한다. 대화 UI·저장·사용량 제한은 `AILearning.jsx`의 것을 그대로 쓴다.
- 답 채점도 실시간이다. 키가 없으면 `check.a`를 펼쳐 보여주는 자가 채점으로 폴백한다.

즉 **뼈대는 사전 생성, 대화는 실시간**이다. 진도바는 네트워크 없이도 정확하다.

## 7. 완주 판정과 coverage 교체

### 7-1 논점 상태

`미학습 → 설명 봄 → 확인 통과` 3단계. 진도바는 **통과** 기준으로 센다.

저장은 `localStorage`, 키 `ailearn-track-progress`, 형태 `{ [leaf_id]: { [point_id]: 2 } }`. 기존 `aiLearningStore`의 저장 관례를 따르고 export/import에 포함시킨다.

### 7-2 coverage를 실측값으로 바꾼다

지금 coverage는 **AI가 대화 끝에 자기 입으로 추정**한다.

```json
{"session_summary":"…","coverage_delta":0.05,"next_topic":{…}}
```

`aiClaudeClient.js`의 세션 종료 규칙에 `coverage_delta`가 0~0.3 추정치로 들어가 있다. 믿을 근거가 없다. 트랙이 생기면 `basic` 회독의 coverage를

```
coverage = 통과한 논점 수 ÷ 그 관의 전체 논점 수
```

로 바꾼다. `coverage_delta`는 `basic`에서 무시하고, 트랙이 없는 회독(`deep` 이후)에서만 지금처럼 쓴다.

**파급** — coverage는 `DDayPlanner`·`WeaknessPanel`·`leafStats`·`proficiencyEngine`·`getDueChapters`가 전부 읽는다. `rollupPhases`가 회독 평균으로 롤업하므로 최상위 필드를 읽는 기존 소비자는 코드 변경 없이 더 정확한 값을 받는다. **읽기 경로는 안 건드리고 쓰기 경로만 바꾼다.**

## 8. 애니메이션 — 새 계층을 만들지 않는다

### 8-1 방식

viz 템플릿 18개는 전부 순수 `params → SVG`다. 그래서 `params`에 `steps`를 허용하고 **`VizRouter` 한 곳**에서 단계 재생기를 얹으면 18개가 전부 애니메이션이 된다. 템플릿 파일은 건드리지 않는다.

```json
{ "template": "supply-demand",
  "params": { "scenario": "소득 증가", "axes": {…} },
  "steps": [
    { "label": "최초 균형",   "shifts": [] },
    { "label": "수요 증가",   "shifts": [{"curve":"D","direction":"right","magnitude":"moderate"}] },
    { "label": "새 균형 확정", "shifts": [{"curve":"D","direction":"right","magnitude":"moderate"}],
      "annotations": {"price_change":{"show_arrow":true},"quantity_change":{"show_arrow":true}} }
  ] }
```

`VizRouter`는 `steps[i]`를 `params` 위에 얕게 병합해 `<Comp params={merged}/>`를 렌더하고, `◀ ▶` 와 재생 버튼, 단계 라벨을 `VizFrame` 툴바 옆에 붙인다. **각 단계의 병합 결과를 기존 `validate(tpl.schema, …)`로 그대로 검증한다** — 새 검증기를 만들지 않는다.

### 8-2 부드러움에 대한 정직한 한계

템플릿은 계산된 좌표를 SVG 속성으로 직접 찍는다. 단계가 바뀌면 좌표가 점프한다.

- **기본**: 단계 교체 + 짧은 크로스페이드. 모든 브라우저에서 동작한다.
- **선·점 기반 템플릿**(SupplyDemand·CostCurves·IsLm·PhillipsCurve 등): SVG 지오메트리 속성에 CSS transition을 걸면 Chrome·Safari에서 곡선이 실제로 미끄러진다. Firefox는 지원이 불완전해 점프로 폴백한다.

이 앱은 Mac·iPhone에서 쓰이므로 실질적으로 미끄러진다. **다만 "모든 템플릿이 부드럽게 움직인다"고 약속하지 않는다.** `// ponytail:` 주석으로 한계와 업그레이드 경로(단계별 SVG를 보간 가능한 동일 명령 path로 생성)를 남긴다.

### 8-3 새 템플릿

미리 만들지 않는다. 트랙 생성 중 "표현할 게 있는데 맞는 템플릿이 없는" 논점이 쌓이는 걸 `--check` 리포트로 보고, 실제로 반복되는 것만 추가한다.

## 9. 파일럿 범위와 검증

### 9-1 범위

**경제학원론 `basic` 97관.** 이유: 애니메이션 효과가 가장 큰 과목(수요공급·비용곡선·IS-LM·필립스 전부 이동하는 그래프)이고, Tier 1 템플릿 18개 중 7개가 경제 전용이라 시각자료 경로를 가장 넓게 검증한다. 대신 필기가 옛 PDF 사다리 방식으로 만들어져 면수 지표 궁합이 나쁜 과목이므로, §2-3의 4강 누락을 포함해 매핑 품질을 함께 점검한다.

### 9-2 검증 — `--check`

`build_topic_track.py --check`가 보고한다. 이게 이 설계의 러너블 체크다.

1. 모든 `src` 앵커가 그 관의 실제 span 범위 안에 있는가 (밖이면 논점이 다른 관에서 새어 들어온 것).
2. 관당 논점 수가 3~40 범위 밖인 관.
3. `viz.template`이 `vizRegistry`에 등록돼 있는가. `steps` 각 단계가 스키마를 통과하는가.
4. `orphans` 총 시간과 상위 구간.
5. 재생성 시 이전 트랙과 `id` 대조 — 사라진 id·새 id를 보고해서 진도 마이그레이션 여부를 판단하게 한다.

Node 쪽은 `steps` 병합 검증에 대한 작은 단위 테스트 하나를 남긴다(`viewer/scripts/` 관례에 맞춰 `node --test`).

### 9-3 순서

1. `build_topic_track.py` 작성, `--limit 2`로 2관만 생성해 육안 검토 (`rm -rf scripts/lectures/__pycache__` 먼저 — 인수인계서 5-1).
2. `--check` 검증기.
3. 품질 합의 후 97관 전체 생성.
4. `VizRouter` 단계 재생 + `viz` 스키마 확장.
5. 진도 저장 모듈 + 「개념 완성」 화면 + `SUB_TABS` 분리.
6. coverage 쓰기 경로 교체.
7. 과목 레벨 트랙(§4-4) 4강 생성.

## 10. 하지 않는 것

- **판서 키프레임을 화면에 띄우기** — 저작권과 용량이 둘 다 걸린다. 판서에만 있던 수식은 트랙 생성 입력으로 들어가 `body`에 흡수된다.
- **강의 시각 노출** — `src`는 내부 앵커로만 쓴다.
- **2·3·4회독·특강(612h)** — 파이프라인이 같다. 트랙이 검증된 뒤 `--phase deep`으로 같은 명령을 돌린다.
- **전 과목 일괄 생성** — 경제학 트랙 품질을 보고 결정한다.
- **트랙 생성기의 자체 매핑** — `align.json`을 신뢰하고 쓴다. 매핑을 다시 짜지 않는다.

## 11. 열린 위험

| 위험 | 대응 |
|---|---|
| 논점 추출이 강의의 곁가지(잡담·다음 강의 예고)를 논점으로 승격 | 프롬프트에 "이 관의 범위를 지킬 것" 규칙 상속. `--check`의 앵커 범위 검사로 후검출 |
