## 1. 무엇을 만드나

관 하나를 열면 상단 탭에서 **개념 완성 · 기출분석 · 심화** 셋 중 하나를 고른다.
세 탭은 같은 단원 체계, 같은 화면 구조, 같은 말풍선 렌더러를 쓴다.

지금 흩어져 있는 것들을 이 셋 안으로 넣는다.

| 지금 | 어디로 |
|---|---|
| 개념 완성 (논점 940) | 개념 완성 |

| 교재 패널 ✅ OX | 개념 완성 (quiz 턴) |
| 교재 패널 🧠 암기 | 개념 완성 (복습 메이트 대사) |
| 교재 패널 🎯 인출 | 개념 완성 관 끝 + 홈 (같은 큐) |
| AI 학습 13개 모드 | **폐지** |
| AI 학습 자유 대화 | 심화 |
| (없음) | **기출분석 — 신규** |

### 성공 기준

1. 관 하나에서 세 탭을 오갈 때 **화면 구조가 바뀌지 않는다**(같은 셸·같은 렌더러).
2. API 키 없이도 **개념 완성과 기출분석을 끝까지 진행**할 수 있다.
3. 학습 중 아무 때나 **끼어들어 묻고, 정확히 그 자리로 돌아온다**.
4. 1차 과목의 심화 대화가 `DeepChat.jsx` 500줄 이하로 선다
   (`AILearning.jsx` 4,114줄은 2차 전용으로 남는다 — §12).

## 2. 접근 — 한 렌더러, 세 트랙

`ConceptScene` 이 `turns` 스키마를 그리는 **유일한 렌더러**가 된다.
세 탭은 무엇을 물리느냐만 다르다.

| 탭 | 트랙 파일 | 저작 |
|---|---|---|
| 개념 완성 | `{unit}.basic.json` | 기존 940논점 + 이번에 증보 |
| 기출분석 | `{unit}.exam.json` | **신규 — 720문항 전부 저작** |
| 심화 | 없음 (실시간) | — |

트랙 파일은 `public/data/study/{과목}/lectures/track/` 에 둔다.
색인은 트랙별로 나눈다 — `_index.json`(개념) · `_index.exam.json`(기출).

**왜 이 접근인가.** 「모든 탭의 디자인이 통일감 있게」를 사람이 지키는 규율이 아니라
구조로 보장한다. 탭마다 화면을 따로 만들면 시간이 지나며 반드시 갈라진다.
한 컴포넌트에 모드 분기를 넣는 방식은 이미 해 봤고, 그 결과가 지금의 4,114줄이다.

**대가.** 기출 문항의 특수 요구(선지 5개·계산식·표)를 `turns` 스키마에 맞춰야 한다.
스키마가 이미 quiz 턴과 viz 를 갖고 있어 큰 무리는 없지만, 맞지 않는 것이 나오면
스키마를 넓히지 말고 **그 문항을 안 넣는** 쪽을 택한다(§10).

## 4. 개념 완성 — 넷을 흡수한다

### 4-1. 교재 전체

강의가 다루지 않은 논점을 교재로 메운다. 이미 22관을 그렇게 채웠고
(`source: "textbook"`), 남은 범위도 같은 방식으로 훑는다.

교재 원문 패널을 **없애지 않는다.** `/교재` 명령으로 연다. 대화가 근거를 못 대면
확인할 데가 있어야 한다.

### 4-2. OX → quiz 턴

교재의 `#### ✅ OX 확인문제` 섹션에 **경제학 기준 507지문**이 있다(17개 단원 전부 보유).
지문 하나가 O/X 2지선다 quiz 턴이 된다.

- 그 관의 논점 중 **주제가 맞는 논점 뒤에** 붙인다. 관 끝에 몰아넣지 않는다 —
  배운 직후에 물어야 인출이다.
- 붙일 논점을 못 찾은 지문은 관 끝 「확인」 묶음으로 간다.
- 변환은 스크립트가 하되 **붙일 자리는 제가 정한다**. 자동 매칭만으로는
  엉뚱한 논점에 붙는다.

### 4-3. 암기법 → 복습 메이트 대사

`#### 🧠 암기법` 섹션(17개 단원 전부 보유)의 두문자·연상법을 그 관 마지막
복습 메이트 턴으로 넣고, 관 완료 화면의 「챙길 것」에도 올린다.

### 4-4. 인출 — 관 안에도, 밖에도

**논점을 통과하는 순간** 그 논점의 quiz·OX 를 `studyDrill.js` 의 SRS
사다리(1→3→7→16→35일)에 올린다. 관을 마칠 때까지 기다리지 않는다 — 관이 20논점이면
첫 논점의 복습 시점이 그만큼 밀린다.
다시 그 관에 들어오면 **만기된 것부터** 묻고, 그 뒤 이어보기 위치로 간다.
홈의 「오늘의 인출」은 과목을 가로질러 그대로 둔다.

**두 곳이 같은 큐를 쓴다.** 따로 만들면 어디서 풀었는지에 따라 복습 주기가 갈린다.

## 5. 기출분석 — 신규

### 5-1. 재료

감정평가사 경제학 기출 **720문항**. 160관에 나누면 관당 평균 4.5문항.
해설은 **720문항 전부** 있고 이미 단계로 쪼개져 있다.

```
① [한계비용 공식] MC = dTC/dQ = 8Q
② [숫자 대입] 32 = 8Q
③ [최종 결과] Q = 4
```

**없는 것: 선지별 「왜 틀렸나」**(`option_meta` 0건). 이것을 제가 저작한다.
오답을 골라도 이유를 못 들으면 깨달음이 없다.

### 5-2. 한 문항의 대화

```
선생    이 문제는 「완전경쟁 이윤극대화」를 묻습니다
        (문제 본문 → 스트림 / 선지 5개 → 하단 도크)
[선택]
깐깐이  ③을 고르셨군요. MC 를 구하지 않고 TC 를 그대로 썼습니다   ← 저작
선생    ① 한계비용 공식 MC = dTC/dQ = 8Q                        ← 해설 단계
선생    ② 숫자 대입 32 = 8Q
선생    ③ 따라서 Q = 4
메이트  이 유형은 이 관에서 12번 나왔습니다                       ← 빈출 데이터
```

선지 도크·정답/내 답 라벨·다시 풀어보기는 개념 완성과 **완전히 같은 컴포넌트**다.

### 5-3. 저작 규칙

- 문항 하나 = point 하나. `id` 는 기출 문항 id 에서 파생한다.
- 해설 단계(①②③)는 **원문을 옮긴다.** 다시 쓰지 않는다 — 검증된 해설이다.
- 선지별 오답 이유는 **틀리는 이유의 유형**을 말한다. 「③은 틀렸습니다」가 아니라
  「MC 를 구하지 않고 TC 를 그대로 썼습니다」.
- 계산 문항은 `viz` 로 그림을 붙일 수 있으면 붙인다. 억지로 만들지 않는다.

## 6. 심화 — 자유 대화 AI 튜터

### 6-1. 걷어내는 것

| | 지금 | 뒤 |
|---|---|---|
| 학습 모드 | 13개 | **0** — 모드 개념 자체를 없앤다 |
| 교재 패널 탭 | 7개 | 1 (`/교재`) |
| 모드별 조건부 자료 로딩 | 있음 | 검색이 대신한다 |

남기는 것은 **자유 대화 하나**. 말풍선은 개념 완성과 같은 렌더러로 그린다.

**파일은 줄이는 게 아니라 새로 만든다.** `AILearning.jsx`(4,114줄)를 깎지 않고
`DeepChat.jsx`(500줄 목표) + `rag.js`(200줄 목표)를 새로 쓴다. 이유는 §12 에 있다 —
2차 시험 과목(답안·양식·논점·실전)은 당분간 지금 화면을 계속 쓴다. 깎으면 그 기능이
같이 사라진다. `AILearning.jsx` 는 2차 전용으로 남았다가, 2차까지 옮긴 뒤 지운다.

### 6-2. 검색 인덱스 — 빌드 때 만든다

```
sync-data → units/G*.md ─ 소제목(####) 단위 청크 ─→ {과목}/rag/{unit}.chunks.json
                                                    [{ id, path, text, terms }]
```

경제학 기준 **청크 1,300개 · 중앙값 472자**. 전체 약 600KB 로 브라우저가 들 수 있다.

### 6-3. 검색은 키 없이 — 생성만 키를 쓴다

**임베딩을 기본으로 쓰지 않는다.** Anthropic 은 임베딩 엔드포인트가 없어
제공자를 바꾸면 인덱스를 다시 만들어야 한다. 어느 제공자든 최소한은 동작해야 한다.

기본은 **어절 + 2-gram 키워드 점수**(BM25 축약형). 한국어 형태소 분석기 없이도
「한계대체율」·「구축효과」 같은 시험 용어는 그대로 매칭된다.

**정직하게 적어 둔다:** 키워드 검색은 임베딩보다 약하다. 「물가가 오르면 실질임금은?」
처럼 용어가 안 겹치는 질문은 잘 못 찾는다. 임베딩은 나중에 제공자가 지원할 때
**추가 선택지**로 연다. 기본을 갈아치우지 않는다.

### 6-4. 프롬프트 예산 — 못 박는다

| 블록 | 내용 | 상한 |
|---|---|---|
| 교재 청크 | 질문 관련 상위 6개 | 3,000자 |
| 이 관 논점 | 제목 + gist 목록 | 600자 |
| 학습 기록 | 아래 다섯 | 800자 |
| 강의 필기 | 이 관 슬라이스 | 800자 |

지금은 `sectionMd || unitMd` 를 통째로 넣는다 — 단원 md 평균 **10만 자**다.
관련 없는 부분까지 매번 들어가고, 질문이 무엇이든 같은 덩어리가 간다.

**학습 기록 다섯**(지금 빠져 있는 것):

1. 개념 완성에서 못 넘은 논점 — 두 번 틀려 답을 본 자리
2. 기출분석에서 틀린 문항 — 번호와 고른 선지
3. 틀린 OX 지문
4. 만기된 인출 항목
5. 사용자 메모

### 6-5. 근거를 밝히게 한다

시스템 프롬프트가 강제한다:

> 교재에서 가져온 내용은 반드시 `[§3-②]` 형태로 출처를 밝혀라.
> 준 청크에 없는 내용은 「교재에 없습니다」라고 말하고 지어내지 마라.

답변의 `[§3-②]` 는 **클릭하면 교재 패널의 그 자리로 이동**한다.
사용자가 튜터 말을 검증할 수 있어야 RAG 가 의미가 있다.

## 7. 학습 중 끼어들어 묻기

요청의 핵심이라 따로 세운다. **세 탭 모두**에 적용된다.

### 7-1. 하단 입력줄에 그냥 쓴다

```
선생    구축효과는 소득 → 화폐수요 → 이자율 → 투자 순서로…
[나]    잠깐, 화폐수요가 왜 소득이 늘면 늘어요?          ← 끼어들기
────────────────────── 샛길 ──────────────────────
선생    거래적 동기 때문입니다. 소득이 늘면 사고파는…      ← 실시간 생성
[나]    아 그럼 투기적 동기는요?
선생    그건 이자율에 반응하는 쪽이라…
──────────────────────────────────────────────
                          [ ↩ 논점으로 돌아가기 ]
선생    …그래서 투자가 줄어듭니다.                       ← 원래 자리 그대로
```

### 7-2. 지키는 것 넷

1. **트랙 상태를 건드리지 않는다.** 끼어들기는 `conceptTurns` 의 `cursor` 를
   움직이지 않는다. 돌아가면 정확히 그 턴이다.
2. **샛길임이 눈에 보인다.** 구분선과 배경으로 「여기부터는 트랙이 아니다」를
   표시한다. 안 그러면 사전 저작 대사와 생성된 답이 섞여, 어디까지가 검증된
   내용인지 알 수 없게 된다.
3. **샛길은 논점에 붙어 남는다.** 다시 오면 「이 논점에서 3번 물었습니다」로
   접혀 있고 펴서 볼 수 있다.
   저장 키는 **`ailearn-side:{leafId}:{pointId}`**. 기존 `ailearn-room:{leafId}`
   (심화 탭의 관 단위 대화)와 **다른 키다** — 논점에 붙은 즉문즉답과 관 전체를 놓고
   하는 대화는 다시 열었을 때 보여야 할 것이 다르다.
4. **측정에 넣지 않는다.** `g: 'none'` — 채점 근거가 없으므로 실력 점수에 섞지
   않는다. 「몇 번 물었나」만 남긴다.

### 7-3. 무엇을 물고 들어가나

- 지금 논점 — 제목·gist·지금까지 나온 대사
- 교재 청크 — 질문 관련 상위 6개 (§6-3)
- 학습 기록 — 이 관에서 틀린 것들 (§6-4)
- 기출분석이면 지금 문항과 내가 고른 선지

그래서 「이거 왜요?」처럼 짧게 물어도 무엇을 가리키는지 안다.

### 7-4. 키가 없으면

입력줄은 그대로 두되, 보내면 이렇게 답한다.

> 물어보려면 API 키가 필요합니다. **설정에서 키 넣기 →**
> 키 없이도 논점 대화와 기출 풀이는 끝까지 진행됩니다.

**학습 자체는 막히지 않는다.** 끼어들기만 잠긴다.

### 7-5. 심화 탭과의 관계

| | 끼어들기 | 심화 탭 |
|---|---|---|
| 범위 | 지금 논점 하나 | 관 전체 |
| 계기 | 진행 중 막힐 때 | 다 익힌 뒤 더 파고 싶을 때 |
| 저장 | 그 논점에 | 그 관에 |

심화 탭을 열면 **그 관에서 했던 샛길 질문들이 먼저 뜬다** — 「이 관에서 이런 걸
물으셨습니다」. 두 곳이 따로 놀지 않게.

## 10. 하지 않는 것

- **기출분석에 실시간 생성을 섞지 않는다.** 섞으면 키 없는 사용자에게
  탭이 반쪽이 된다. 저작분만으로 끝까지 굴러가야 한다.
- **심화 탭에 트랙 파일을 만들지 않는다.** 만들면 개념 완성과 같아진다.
- **탭마다 다른 말풍선·선택지 컴포넌트를 만들지 않는다.**
- **`turns` 스키마를 기출 때문에 넓히지 않는다.** 안 맞는 문항은 넣지 않는다.
- **임베딩을 기본 검색으로 만들지 않는다.** 제공자 종속이 생긴다.
- 모드 추천(`recommendMode`)·자동 암기카드 생성·형광펜 가리기 — **폐지**.
  13개 모드와 함께 사라진다.

## 11. 순서와 크기

| 단계 | 일 | 크기 | 키 필요 |
|---|---|---|---|
| 1 | 3탭 셸 + 렌더러 공용화 | 중 | — |
| 2 | 심화 탭 걷어내기 (4,114 → 500줄) | 중 | — |
| 3 | RAG 인덱스 + 키워드 검색 + 근거 표기 | 중 | 생성만 |
| 4 | 끼어들기 + 돌아가기 | 중 | 생성만 |
| 5 | OX 507지문 → quiz 턴 | 중 | — |
| 6 | 암기법 → 메이트 대사 | 소 | — |
| 7 | 인출 관 안 연결 | 소 | — |
| 8 | **기출분석 720문항 저작** | **대** | — |

8번이 압도적으로 크다. 1~7 을 먼저 끝내 **화면이 돌아가게 한 뒤**, 8번을 관 단위로
채워 나간다. 그래야 중간에 멈춰도 쓸 수 있는 물건이 남는다.

**구현 계획은 둘로 나눈다.** 1~7 은 시스템이고 8 은 저작이다. 성격이 달라 한 계획에
넣으면 「태스크 하나가 720문항」 같은 항목이 생긴다.

- 계획 ① 1~7 — 이 스펙으로 바로 작성한다.
- 계획 ② 8 — ① 이 끝나 `{unit}.exam.json` 을 실제로 읽는 화면이 선 뒤에 쓴다.
  그래야 저작 형식을 화면에 대고 확정할 수 있다. 진행 기록은 심화 보충 때 쓴
  `_progress.json` 방식을 그대로 쓴다.

## 12. 열린 위험

**기출 720문항 저작이 길다.** 관 단위로 커밋하고 진행 기록을 남긴다
(심화 보충 때 쓴 `_progress.json` 방식). 중간에 멈춰도 어디까지 했는지 알 수 있어야 한다.

**OX 지문을 붙일 논점을 못 찾는 경우.** 자동 매칭이 엉뚱한 자리에 붙이면 학습이
망가진다. 매칭은 제안까지만 하고 **붙일 자리는 사람이 정한다.**

**키워드 검색의 한계.** §6-3 에 적었다. 검색이 빈손이면 튜터가 「교재에서 못 찾았습니다」
라고 말하게 한다 — 조용히 지어내는 것보다 낫다.

**AILearning.jsx 를 줄이며 잃는 기능.** 13개 모드 중 2차 시험용(답안·양식·논점·실전)은
경제학에 없지만 다른 과목에는 쓰인다. **1차 과목만 새 3탭으로 옮기고, 2차 과목은
당분간 지금 화면을 유지한다.** 한꺼번에 갈아치우지 않는다.
