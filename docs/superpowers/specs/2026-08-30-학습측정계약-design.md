# 학습 측정 계약 — AI학습·드릴·문제풀이 3모드 통합 실력 측정

> 2026-08-30 설계. 대상: 1차 5과목 + 2차 3과목 전체.
> 임고닷컴 「국어 지식그래프 개발자 기술 명세」의 설계 원리를 감정평가사 앱에 옮긴다.
> 원본 명세와 충돌하면 이 문서가 우선한다 — 우리는 콘텐츠를 새로 짓지 않고 **이미 있는 것을 정확히 잰다.**

## 1. 문제

실력 리포트가 실제 실력과 어긋난다. 사용자가 지목한 어긋남이 넷이고, 넷 다 같은 뿌리에서 나온다.

| 증상 | 원인 |
|---|---|
| 찍어서 맞힌 게 실력으로 잡힌다 | 5지선다 정답률을 그대로 쓴다. 찍기 하한 20%가 점수에 섞인다 |
| 안 푼 범위가 무시된다 | `score = mSum / wSum` — **측정된 관만 분모에 든다** (`proficiencyEngine.js:169`) |
| 읽기만 한 게 실력이 된다 | AI 커버리지가 `U` 축으로 0.20 가중돼 점수에 들어간다 |
| 모의고사 점수와 다르다 | 위 셋의 합 |

뿌리는 하나다. **엔진이 증거의 종류를 구분하지 않는다.** 지금은 세 축(`U` 이해 0.20 / `R` 인출 0.35 / `A` 적용 0.45)의 가중평균이고, 그 안에서 "무엇으로 잰 값인가"는 사라진다.

### 1-1 실측 (2026-08-30)

```
기출 12,039 · 연습 35,217 · 합계 47,256문항
taxonomy 매핑된 기출        10,360 / 12,039  (86%)
기출 난이도 분포            3이 9,546개 (79%) — 사실상 단일값
option_meta(선지 근거)      부동산 2,550/2,550 · 회계 8,084/8,085 · 경제 2,240(principle 없음)
                            민법 0 · 법규 0 · 기출 0
principle(법리) 태그        부동산 12,735개(고유 1,790) · 회계 6,245개(고유 1,712)
```

두 가지가 설계를 바꿨다.

- **난이도 태그는 못 쓴다.** 기출의 79%가 값 3이라 IRT·Rasch 보정이 정보를 못 얻는다. 연습문제는 1~5 고르게 분포하나, 연습문제 성적으로 기출 실력을 추정하는 것은 별개 문제다. 보류한다.
- **`principle` 태그가 이미 있다.** 명세의 "혼동짝·오개념" 층이 부동산·회계 두 과목에는 **콘텐츠 생산 없이** 존재한다.

### 1-2 지금 버려지는 신호

전부 이미 계산되는데 저장만 안 한다. **지금 안 남기면 소급 복원이 불가능하다.**

| 신호 | 어디서 계산되나 | 어디서 사라지나 |
|---|---|---|
| `assisted` (2회 오답 후 답을 열어 통과) | `conceptTurns.js:79` | `trackProgress`가 `max(NEW/SEEN/PASSED)`만 저장 |
| 시도 횟수 `picked.length` | `conceptTurns.js:74` | 같음 |
| 계산 연습의 채점 주체 | `ParsedText.jsx:686` `checkTable`(기계) vs `:689` `grade`(자기) | **둘 다 `kind:'prac'`** — 구분 불가 |

| 콘텐츠 판(revision) | — | 없음 |

## 2. 성공 기준

**사용자가 고른 기준은 "체감과의 일치"다.** 이건 자기 기준이라 모델이 체감에 맞춰 휘어도 알 수 없다. 그래서 설계를 이렇게 잡는다.

1. **점수를 맞히는 대신 근거를 드러낸다.** 관마다 어떤 증거로 그 점수가 나왔는지 리포트에 그대로 쓴다. 체감과 다르면 어느 증거 때문인지 즉시 보인다.
2. **모르는 것은 모른다고 한다.** 증거가 부족하면 숫자 대신 구간, 더 부족하면 "판단 보류".
3. **자기검증을 붙인다** (F축). 응답 전 예측 `p`를 남기고 사후 대조한다. 체감과 어긋날 때 *모델이 틀렸는지 체감이 틀렸는지* 가릴 수 있어야 한다.

모의고사 대조는 `quiz-mock-history`(최대 50건)가 이미 있어 나중에 거의 공짜로 붙는다. **지금은 만들지 않는다.**

## 3. 설계 원칙

명세의 불변 원칙을 우리 맥락으로 옮긴다.

1. **엔진은 기능을 모른다.** 계약(레코드 스키마 + 무게표)만 안다. OX인지 와꾸인지 분개인지 모른다.
2. **노출은 실력이 아니다.** 채점되지 않은 활동은 무게 0. 진도 지표로만 남는다.
3. **measured와 inferred를 섞지 않는다.** 추정치는 플래그를 달고, 표시에서 구분한다.
4. **추측 숫자를 노출하지 않는다.** 불확실하면 구간, 더 불확실하면 침묵.
5. **소급 불가 신호를 먼저 배포한다.** 나머지는 과거 기록으로 다시 계산할 수 있다.

## 4. 측정 계약 v1

### 4-1 응답 레코드 (모든 모드 공통)

```js
{
  v: 1,                 // 계약 버전
  id,                   // 문항·논점·카드 고유 id
  leaf,                 // 단원 키 (1차 taxonomy leaf / 2차 논점 unit)
  path: [],             // 계층 경로. 깊이 무관 — 1차 4단, 2차 2단
  subject, stage,       // 과목 id, 1|2

  ts, ms,               // 응답 시각, 소요 시간(ms)
  correct,              // true | false | null(채점 불가)
  score,                // 0~1 부분점수. correct=null이면 이 값을 쓴다

  f,                    // 형식  'recog' | 'recall' | 'produce' | 'write'
  g,                    // 채점  'machine' | 'ai' | 'human' | 'self' | 'none'
  strict,               // (선택) 형식이 recog이나 찍기 내성이 높은 경우 true

  assisted,             // 도움받아 통과했는가
  tries,                // 몇 번 만에
  p,                    // 응답 직전 모델 예측 P(correct). 소급 불가
  rev,                  // 콘텐츠 판(revision). 없으면 0

  meta                  // 모드별 부가: chosen, principle, rubric, timed …
}
```

`correct`와 `score`는 배타가 아니다. 1차는 `score = correct ? 1 : 0`으로 채워 **하나의 식으로 흡수**한다.

### 4-2 무게표 `weights@v1` — 데이터로 분리, 버전을 찍는다

무게는 코드가 아니라 **버전 찍힌 데이터**다. P5에서 실측 보정할 때 과거 점수를 옛 표로 재계산할 수 있어야 한다. (명세의 `graph_version`과 같은 방식.)

| f \ g | machine | ai | human | self | none |
|---|---|---|---|---|---|
| **produce** 산출·계산 | **3.0** | 2.5 | 3.0 | 0.5 | 0 |
| **write** 서술 | — | 2.5 | **3.0** | 0.6 | 0 |
| **recall** 백지 인출 | 2.2 | 2.0 | 2.4 | 0.4 | 0 |
| **recog** 선택지 | 1.0 | 0.9 | 1.0 | 0.3 | 0 |

**예외 하나** — `recog + machine + strict` = **2.0**. AI 논점 quiz가 여기 해당한다. 형식은 선택지지만 2회 오답 시 통과를 박탈(`assisted`)하므로 찍기 내성이 실질적으로 높다. 예외는 이 하나뿐이고, 표에 명시해 둔다.

`human`은 지금 쓰이지 않지만 **미리 예약한다.** 스터디 첨삭·강사 채점이 들어올 자리다. 나중에 추가하면 과거 기록에 소급이 안 된다.

### 4-3 상한표 `caps@v1`

상한은 무게에서 **유도하지 않는다.** 별도로 조율된 값이고, 선형식으로는 이 서열이 나오지 않는다. `weights@v1`과 같은 파일에 함께 버전을 찍는다.

| 그 관에서 관측된 최고 무게 `w_max` | cap |
|---|---|
| 3.0 (produce·machine / human) | 100 |
| 2.5 (ai 산출·서술) | 85 |
| 2.2 (recall·machine) · 2.0 (recog·strict) | 73 |
| 1.0 (recog·machine) | **65** |
| 0.4~0.6 (self) | 50 |
| 0 (none) | 미측정 |

객관식만 있으면 아무리 맞혀도 **65가 상한**이다. "재인은 확인됐고 인출은 미확인"이 그 관의 정직한 상태다.

### 4-4 감쇠표 `halflife@v1`

§7-B가 쓴다. 형식 `f`로만 키를 잡는다.

| f | S (일) |
|---|---|
| produce | 120 |
| write | 90 |
| recall | 60 |
| recog | 45 |

`g:'self'` 레코드는 여기에 **×0.5**를 곱한다 (자기보고는 더 빨리 신뢰를 잃는다). `g`가 감쇠에 영향을 주는 곳은 여기뿐이다.

**튜닝 가능한 값은 `weights@v1` · `caps@v1` · `halflife@v1` 세 표에만 산다.** 코드에 상수를 박지 않는다.

### 4-5 계약 위반 방지

- **`record()` 단일 진입점.** 지금은 5곳이 제각각 `localStorage`를 만진다. 전부 이 함수를 거치게 한다.
- `f` 또는 `g` 미지정 → **개발 빌드에서 throw.** 새 기능이 계약을 빠뜨리는 것을 막는다.
- `g:'ai'` 레코드는 **일치도 검증 플래그가 켜지기 전까지 점수 반영 금지**, 표시만 (명세 §7.1).
- `v` 불일치 레코드는 그 버전의 표로 계산한다.

## 7. 점수 산출

### A. 사후분포 — Wilson 점추정에서 Beta 구간으로

```
α = 1 + Σ wᵢ·scoreᵢ            β = 1 + Σ wᵢ·(1 − scoreᵢ)
m = α/(α+β)                    var = αβ / ((α+β)²(α+β+1))
M = cap × m                    구간 = cap × (m ± 1.96·√var)
```

- 표시는 `68`이 아니라 **`68 (52–81)`**
- 구간 폭 > 30점 → 숫자를 숨기고 **"판단 보류 — 증거 부족"**
- 체감 대조에 결정적이다. 구간이 넓으면 **앱도 모르는 것**이고, 그건 체감이 틀렸다는 뜻이 아니다.

### B. 감쇠는 점수가 아니라 무게에 건다

현재 엔진은 `M = Mraw × (0.4 + 0.6·Rnow)`로 **점수를 깎는다.** 이건 "실력이 떨어졌다"는 주장이고 근거가 없다. 실제로 아는 것은 "오래돼서 지금은 모르겠다"뿐이다.

```
w_eff = w × exp(−Δt / S)          S = halflife@v1[f] × (g === 'self' ? 0.5 : 1)
```

무게가 줄면 α·β가 함께 줄어 **구간이 저절로 넓어진다.** 점수가 내려가는 게 아니라 **불확실해진다.** 복습 우선순위와도 자연스럽게 맞물린다.

### C. 계층적 축소 — 안 푼 관을 형제로 추정

커버리지 게이트(침묵)보다 정직한 방법이 있다.

```
α_l = κ·ᾱ_parent + Σ w·score          κ = 2 (가상 관측 2개)
β_l = κ·β̄_parent + Σ w·(1 − score)
```

- `path[]`의 **바로 위 노드**를 부모로 잡는다. 깊이에 무관하므로 1차(4단)와 2차(2단)가 같은 코드를 쓴다.
- **measured / inferred 분리**: 그 관의 **실측 레코드에 한해** `n_eff = Σ w_eff`를 구하고, `n_eff ≥ 3`이면 measured, 아니면 inferred. 부모에서 빌려온 `κ·ᾱ`는 `n_eff`에 넣지 않는다 — 넣으면 모든 관이 measured가 된다.
- inferred는 리포트에서 점선·회색. **예상 점수에는 포함**하되 넓은 구간으로 불확실성이 그대로 드러난다.

침묵하는 대신 *"형제 관들을 보면 이 정도일 텐데, 매우 불확실하다"* 고 말한다.

### D. 자기보고 관대도 — 개인별·stage별 추정

`self` 무게 0.4는 고정 상수였다. 데이터로 뽑을 수 있다.

```
// 관 l 마다 두 사후평균을 따로 낸다 (자기채점만 / 객관채점만)
관대도 G = median_l ( m_self(l) − m_obj(l) )     // 두 증거가 모두 있는 관 l 들에서
w_self  = w_base × clamp(1 − 2G, 0.1, 1.2)
```

평균이 아니라 **중앙값**을 쓴다. 관 하나의 극단값이 전체 무게를 흔들면 안 된다. 표본 관이 5개 미만이면 보정하지 않는다.

같은 관에 자가채점과 객관채점(`machine`/`ai`/`human`)이 **둘 다 있는 관**만 표본으로 쓴다. OX를 관대하게 누르면 무게가 0.1까지 내려가고, 엄격하면 0.6까지 오른다.

**1차와 2차 관대도는 분리한다.** 2차는 자기채점 4단(85/70/50/30)이 기본이라 관대해지기 쉽고, 1차 OX와 성격이 다르다.

기존 `calib`(과신 지표: `knowN`/`knowWrong`/`lowN`/`lowCorrect`)은 지금 표시만 하고 버려진다. 이 추정의 보조 입력으로 재활용한다.

표본 부족 시 기본값 유지.

### E. 법리 횡단 약점 — `principle` 집계

가장 값싸고 효과가 크다.

```
오답 → meta.chosen (선지 번호, 1-based) → option_meta[chosen − 1].principle → 관을 가로질러 누적
```

`meta.chosen`은 `quiz-progress-v1`의 `sel`을 계약 형식으로 옮긴 값이다. `option_meta`가 없는 문항(기출 전체·민법·법규)은 건너뛴다.

*"제23·31·47관에서 전부 「감가수정 = 회계 감가상각」으로 틀렸다"* — **관이 아니라 법리 단위의 약점**이 나온다. 명세의 지식그래프가 노리던 것의 실질을 콘텐츠 생산 없이 얻는다.

**한계를 정직하게 표시한다: 부동산·회계만.** 민법·법규·기출 본체에는 태그가 없다.

### F. 예측 검정 — 체감의 심판

응답 **전에** 모델이 `p = P(맞힐 것)`을 기록하고 사후 대조한다.

```
Brier = mean((p − y)²)      // 0.25 = 동전던지기. 낮을수록 좋다
```

매 응답이 검증 표본이다. 외부 데이터가 필요 없다. 리포트에 *"최근 200응답 예측오차 0.17"*.

**`p`는 응답 시점에 저장해야 한다. 소급 불가다** — 모델을 바꾸면 그때의 예측을 복원할 수 없다.

### 두 숫자로 분리

- **측정 실력** — measured 관만. 지금 점수의 정직한 이름.
- **예상 시험 점수** — 전체 관 분모, inferred 포함, 구간 병기. stage별 합격 규칙(1차: 과목 40 / 평균 60)을 적용한다.

## 8. 2차 특유 처리

1차 모델을 그대로 쓰면 안 되는 네 가지.

**① 부분점수.** 2차는 0/1이 아니다. `score ∈ [0,1]`을 Beta에 그대로 넣는다(§7-A). 1차는 `score = correct ? 1 : 0`이므로 **같은 식이 둘 다 흡수**한다.

**② 자기채점이 기본**이라 관대도 보정(D)이 1차보다 중요하다. §7-D에서 stage별로 분리한다.

**③ 모범답안 없는 논점** = `g:'none'`, 무게 0. 채점 근거가 없는데 점수를 매기지 않는다. 대신 **"채점 불가 논점 N개"**를 커버리지 결손으로 노출한다 — 콘텐츠 생산 우선순위가 여기서 나온다.

**④ 계층 구조가 다르다.** 1차는 `index_kind:'taxonomy'`(과목→장→절→관), 2차는 `'units'`(단원→논점). §7-C를 `path[]` 깊이 무관으로 구현해 두 구조가 같은 코드를 쓴다.

## 9. 단계

| | 내용 | 되돌릴 수 있나 |
|---|---|---|
| **P0** | **계약 v1 동결 + 기록 어댑터.** 기존 5개 저장소를 계약 형식으로 남기기 시작. 소급 불가 6종 회수. **화면 변화 0** | ❌ **불가** |
| **P1** | 기출↔leaf 매칭률 측정 → 무게표 엔진 (A·B) | 가능 |
| **P2** | 계층 축소 (C) + 리포트 근거·구간 노출 | 가능 |
| **P3** | **2차 연결** — 논술 자기채점·AI 채점을 계약으로 흘려보냄 | 가능 |
| **P4** | 법리 집계 (E) — 부동산·회계 | 가능 |
| **P5** | 관대도 (D) · 예측 검정 (F) — 표본이 쌓인 뒤 | 가능 |

**P0에서 화면은 하나도 바뀌지 않는다.** 기록만 계약 형식으로 남기기 시작한다. 그래야 P1~P5를 과거 데이터로 소급 계산할 수 있다.

**P1의 첫 작업은 "기출↔leaf 매칭률 측정"이다.** 지금 기출은 제목 문자열 매칭(`titleMap.get(norm(q.taxItemName))`)으로 leaf에 붙는다. 실패하면 그 관의 `recog` 증거가 통째로 사라진다. taxonomy 매핑 자체가 86%(10,360/12,039)이므로 그것이 상한이고, 문자열 매칭 실패분은 그 아래다. **매칭률을 모르고 엔진을 고치면 헛일이 될 수 있어 먼저 잰다.**

## 10. 하지 않을 것

재제안 시 이 절로 거절한다.

- **IRT / Rasch 난이도 보정** — 기출 난이도의 79%가 값 3이라 정보가 없다.
- **지식그래프 신규 구축(항목·자질 축·혼동짝)** — `principle` 태그가 이미 그 일을 한다. 47,256문항 선지를 개념에 매핑하는 콘텐츠 사업은 지금 필요 없다.
- **DKT / SAKT 등 딥러닝 지식추적** — 단일 학습자 데이터로는 과적합만 한다.
- **매 문항 확신도 입력** — `assisted`가 이미 "알고 맞혔나"의 답이고, `produce`는 애초에 찍기가 불가능하다. 탭 비용을 지불할 이유가 없다.
- **가중평균 U/R/A 유지** — 증거 종류를 지우는 구조 자체가 문제의 뿌리다.
- **점수에 감쇠 곱하기** — 오래된 것은 낮은 것이 아니라 모르는 것이다.
