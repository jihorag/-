## 1. 문제

실력 리포트가 실제 실력과 어긋난다. 사용자가 지목한 어긋남이 넷이고, 넷 다 같은 뿌리에서 나온다.

| 증상 | 원인 |
|---|---|
| 찍어서 맞힌 게 실력으로 잡힌다 | 5지선다 정답률을 그대로 쓴다. 찍기 하한 20%가 점수에 섞인다 |
| 안 푼 범위가 무시된다 | `score = mSum / wSum` — **측정된 관만 분모에 든다** (`proficiencyEngine.js:169`) |
| 읽기만 한 게 실력이 된다 | AI 커버리지가 `U` 축으로 0.20 가중돼 점수에 들어간다 |
| 모의고사 점수와 다르다 | 위 셋의 합 |

뿌리는 하나다. **엔진이 증거의 종류를 구분하지 않는다.** 지금은 세 축(`U` 이해 0.20 / `R` 인출 0.35 / `A` 적용 0.45)의 가중평균이고, 그 안에서 "무엇으로 잰 값인가"는 사라진다.

### 1-1 실측 (2026-08-30)

```

  taxonomy 매핑된 기출          10,360 / 12,039  (86%)
```

세 가지가 설계를 바꿨다.

- **난이도 태그는 못 쓴다.** 기출의 79%가 값 3이라 IRT·Rasch 보정이 정보를 못 얻는다. 연습문제는 1~5 고르게 분포하나, 연습문제 성적으로 기출 실력을 추정하는 것은 별개 문제다. 보류한다.
- **`principle` 태그가 이미 있다.** 명세의 "혼동짝·오개념" 층이 부동산·회계 두 과목에는 **콘텐츠 생산 없이** 존재한다.
- **2차는 한 문항이 단일 채점 단위가 아니다.** 논점 다중·형식 혼재·배점 8배 차·출처 신뢰도 차이. §4-1의 레코드 단위를 문항이 아니라 **채점 단위**로 잡아야 하는 이유다.

## 2. 성공 기준

**사용자가 고른 기준은 "체감과의 일치"다.** 이건 자기 기준이라 모델이 체감에 맞춰 휘어도 알 수 없다. 그래서 설계를 이렇게 잡는다.

1. **점수를 맞히는 대신 근거를 드러낸다.** 관마다 어떤 증거로 그 점수가 나왔는지 리포트에 그대로 쓴다. 체감과 다르면 어느 증거 때문인지 즉시 보인다.
2. **모르는 것은 모른다고 한다.** 증거가 부족하면 숫자 대신 구간, 더 부족하면 "판단 보류".
3. **자기검증을 붙인다** (§8-F). 응답 전 예측 `p`를 남기고 사후 대조한다. 체감과 어긋날 때 *모델이 틀렸는지 체감이 틀렸는지* 가릴 수 있어야 한다.

모의고사 대조는 `quiz-mock-history`(최대 50건)가 이미 있어 나중에 거의 공짜로 붙는다. **지금은 만들지 않는다.**

## 3. 설계 원칙

1. **엔진은 기능을 모른다.** 계약(레코드 스키마 + 표들)만 안다. OX인지 와꾸인지 분개인지 모른다.
2. **노출은 실력이 아니다.** 채점되지 않은 활동은 무게 0. 진도 지표로만 남는다.
3. **measured와 inferred를 섞지 않는다.** 추정치는 플래그를 달고, 표시에서 구분한다.
4. **추측 숫자를 노출하지 않는다.** 불확실하면 구간, 더 불확실하면 침묵.
5. **소급 불가 신호를 먼저 배포한다.** 나머지는 과거 기록으로 다시 계산할 수 있다.
6. **다른 축을 곱해 섞지 않는다.** 증거 무게(신뢰도) · 배점(시험 비중) · 실력/수행 축은 끝까지 분리해서 나른다.

## 4. 측정 계약 v1

### 4-1 응답 레코드 — 단위는 「문항」이 아니라 「채점 단위」

실무 기출 한 문항에 소물음이 0~11개 있고, 그 안에 계산(`produce`)과 설명(`write`)이 공존한다. 문항 단위 레코드로는 담을 수 없다. **채점되는 최소 단위마다 레코드 하나**를 남긴다.

```js
{
  v: 1,                 // 계약 버전
  id,                   // 채점 단위 고유 id (소물음 id)
  parent,               // 상위 문항 id. 소물음이 없으면 id와 같다
  leaf,                 // 주 단원 키 (1차 taxonomy leaf / 2차 논점 unit)
  path: [],             // 계층 경로. 깊이 무관 — 1차 4단, 2차 2단
  subject, stage,       // 과목 id, 1|2

  axis,                 // 'knowledge' | 'performance'      ← 실력 점수는 knowledge만
  ts, ms,               // 응답 시각, 소요 시간(ms)
  correct,              // true | false | null(채점 불가)
  score,                // 0~1. correct=null이면 이 값을 쓴다

  f,                    // 형식  'recog' | 'recall' | 'produce' | 'write'
  g,                    // 채점  'machine' | 'ai' | 'human' | 'self' | 'none'
  strict,               // (선택) recog이나 찍기 내성이 높으면 true
  nopt,                 // (f='recog'일 때) 선택지 수. 찍기 하한 보정용

  src,                  // 출처  'official' | 'gs' | 'practice' | 'ai' | 'internal'
  pts,                  // 배점. 예상 시험 점수 집계에만 쓴다 (무게와 곱하지 않는다)
  rep,                  // 그 채점 단위의 노출 회차 (1 = 처음)
  prevTs,               // 직전 응답 시각. 반복 감쇠 회복 계산용

  assisted, tries,      // 도움받아 통과했는가 · 몇 번 만에
  p,                    // 응답 직전 모델 예측 P(correct). 소급 불가
  rev,                  // 콘텐츠 판(revision). 없으면 0

  meta                  // chosen, principle, rubric, timed, alsoLeaves[] …
}
```

`correct`와 `score`는 배타가 아니다. 1차는 `score = correct ? 1 : 0`으로 채워 **하나의 식으로 흡수**한다.

한 채점 단위가 여러 논점에 걸치면(2차 `logicalPoints` 2개 이상, 1,528문항) **주 `leaf` 하나에만 점수를 싣고** 나머지는 `meta.alsoLeaves[]`에 부수 기록한다. 점수를 나눠 싣지 않는다 — 나누는 순간 근거를 설명할 수 없게 된다.

### 4-2 유효 무게 — 다섯 계수의 곱

```
w_eff = weights[f][g] × guess(nopt) × source[src] × repeat(rep, Δt_prev) × decay(Δt_now)
```

**두 개의 Δt를 혼동하지 않는다.**

| | 정의 | 뜻하는 것 |
|---|---|---|
| `Δt_prev` = `ts − prevTs` | 직전 응답과 이번 응답 사이 | 간격이 짧으면 문항 기억. §4-6 |
| `Δt_now` = `now − ts` | 이번 응답 이후 지금까지 | 오래됐으면 지금은 모를 수 있다. §4-7 |

각 계수를 아래 표에서 정한다. **튜닝 가능한 값은 전부 표에만 살고 코드에 상수를 박지 않는다.** 표는 함께 버전을 찍어 `tables@v1`로 묶는다.

### 4-3 `weights@v1` — 형식 × 채점 주체

| f \ g | machine | ai | human | self | none |
|---|---|---|---|---|---|
| **produce** 산출·계산 | **3.0** | 2.5 | 3.0 | 0.5 | 0 |
| **write** 서술 | — | 2.5 | **3.0** | 0.6 | 0 |
| **recall** 백지 인출 | 2.2 | 2.0 | 2.4 | 0.4 | 0 |
| **recog** 선택지 | 1.0 | 0.9 | 1.0 | 0.3 | 0 |

**예외 하나** — `recog + machine + strict` = **2.0**. AI 논점 quiz가 여기 해당한다. 형식은 선택지지만 2회 오답 시 통과를 박탈(`assisted`)하므로 찍기 내성이 실질적으로 높다. 예외는 이 하나뿐이다.

`human`은 지금 쓰이지 않지만 **미리 예약한다.** 스터디 첨삭·강사 채점이 들어올 자리다. 나중에 추가하면 과거 기록에 소급이 안 된다.

### 4-4 `guess@v1` — 찍기 하한 보정 (`f='recog'`에만)

같은 "선택지 문제"라도 5지선다는 찍기 하한 20%, OX는 **50%**다. 같은 무게로 세면 사용자가 처음 지적한 문제를 형식만 바꿔 반복하게 된다.

```
guess(nopt) = (1 − 1/nopt) / 0.8          // 5지선다를 1.0으로 정규화
```

| nopt | 2 (OX) | 3 | 4 | 5 | 그 외/미상 |
|---|---|---|---|---|---|
| 계수 | **0.625** | 0.833 | 0.938 | **1.0** | 1.0 |

`f ≠ 'recog'`이면 계수 1.0이다.

### 4-5 `source@v1` — 출처 신뢰도

`2차-5단계-문제설계-plan.md`가 자체제작 문항을 스스로 이렇게 진단했다: 본문 median **150자**(기출 1,827자) · 자료블록 거의 없음 · 가짜 난이도5 · **폐기/재제작 대상**. 그런 문항으로 잰 실력은 시험 실력이 아니다.

| src | 계수 | 비고 |
|---|---|---|
| `official` 기출 | **1.0** | 2차 446문 |
| `gs` 스터디 | 0.8 | 581문 |
| `practice` 자체제작 | **0.5** | 1,493문. 재제작 후 상향 |
| `ai` AI 생성 | 0.3 | 12문 |
| `internal` 드릴·논점 quiz 등 | 0.9 | 강의·교재 기반 |

### 4-6 `repetition@v1` — 회독 오염 보정

`PRODUCT.md`: *"회독 축이 제품 전체를 관통한다."* 합격수기: *"기출 7~8회독, 틀린 것만 재풀이."*

**같은 문항을 일곱 번째 맞히는 것은 그 문항의 답을 외운 것일 수 있다.** Beta는 독립 시행을 가정하므로 정면으로 위배된다. 보정하지 않으면 **회독할수록 점수가 부풀어 오른다.**

다만 **간격이 길면 문항 기억이 아니라 진짜 인출**이다. 간격에 따라 회복하게 만든다.

```
repeat(rep, Δt) = 1 − (1 − ρ^(rep−1)) × exp(−Δt / S)      ρ = 0.6
                                                            Δt = 직전 응답 이후 경과
                                                            S  = halflife@v1[f]
```

- 방금 또 푼 2회차 → `1 − (1−0.6)·1 = 0.6`
- 오래 지난 2회차 → `→ 1.0` (완전 회복)
- 방금 또 푼 5회차 → `1 − (1−0.13)·1 = 0.13`

`rep`은 앱의 `progress[id].reviewed`를 그대로 옮긴다. **처음 보는 문항이 가장 무거운 증거**라는 것이 이 표의 요지다.

### 4-7 `halflife@v1` — 시간 감쇠

§8-B와 §4-6이 함께 쓴다. 형식 `f`로만 키를 잡는다.

| f | S (일) |
|---|---|
| produce | 120 |
| write | 90 |
| recall | 60 |
| recog | 45 |

`g:'self'` 레코드는 여기에 **×0.5**를 곱한다(자기보고는 더 빨리 신뢰를 잃는다). `g`가 감쇠에 영향을 주는 곳은 여기뿐이다.

### 4-8 `caps@v1` — 상한

상한은 무게에서 **유도하지 않는다.** 별도로 조율된 값이고 선형식으로는 이 서열이 나오지 않는다. `w_max`는 그 관에서 관측된 **`weights@v1` 원값**의 최대치다(다른 계수를 곱하기 전).

| `w_max` | cap |
|---|---|
| 3.0 (produce·machine / human) | 100 |
| 2.5 (ai 산출·서술) | 85 |
| 2.2 (recall·machine) · 2.0 (recog·strict) | 73 |
| 1.0 (recog·machine) | **65** |
| 0.4~0.6 (self) | 50 |
| 0 (none) | 미측정 |

객관식만 있으면 아무리 맞혀도 **65가 상한**이다. "재인은 확인됐고 인출은 미확인"이 그 관의 정직한 상태다.

### 4-9 계약 위반 방지

- **`record()` 단일 진입점.** 지금은 5곳이 제각각 `localStorage`를 만진다. 전부 이 함수를 거치게 한다.
- `f` · `g` · `axis` 미지정 → **개발 빌드에서 throw.** 새 기능이 계약을 빠뜨리는 것을 막는다.
- `f='recog'`인데 `nopt` 없음 → 경고 후 1.0으로 처리(하한을 모르면 5지로 가정하지 않는다는 뜻이 아니라, 알 수 없음을 로그로 남긴다).
- `g:'ai'` 레코드는 **일치도 검증 플래그가 켜지기 전까지 점수 반영 금지**, 표시만 (명세 §7.1).
- `v` 불일치 레코드는 그 버전의 표로 계산한다.

## 5. 범위 정의 — 예상 시험 점수의 분모

`PRODUCT.md`에 두 종류의 "제외"가 이미 있고, 성격이 완전히 다르다. 구분하지 않으면 예상 점수가 무의미해진다.

| 범위 | 정의 | 예상 시험 점수 분모 |
|---|---|---|
| **시험 범위** | 실제 출제 범위 전체 | ✅ **기본 분모** |
| **학습 범위** | 강의·교재가 다룬 부분. 재정학 61관은 **어느 회독 강의에도 없어** 개념 완성 목차에서 제외 | ❌ 분모가 아니다 |
| **포기 범위** | "과목별 목표·버리기 보드"로 전략적으로 버린 부분 | ❌ 빼지 않는다 |

**버려도 시험에는 나온다.** 포기 범위를 분모에서 빼면 예상 점수가 실제보다 높게 나오고, 그건 사용자가 지적한 "안 푼 범위가 무시된다"의 재발이다.

- 기본 표시: **시험 범위 기준** 예상 점수
- 부가 표시: "버림 반영" 값 — 전략이 실제로 몇 점을 포기하는 것인지 보여주는 용도
- 학습 범위 밖(재정학 등)은 `inferred`로도 추정하지 않는다. 형제 관이 없으므로 **"측정 불가"**로 남기고 커버리지 결손에 표시한다

## 8. 점수 산출

### 축 분리 — knowledge와 performance는 절대 합치지 않는다

합격수기가 가리키는 결정적 행동(완주·선구안·시간 관리)은 **실력과 독립된 축**이다. `correct/score`로 억지로 표현하면 실력 점수가 오염된다.

- **실력 점수(θ)**: `axis='knowledge'` 레코드만으로 계산한다.
- **수행 지표**: `axis='performance'`를 별도 패널에 낸다. 점수화하지 않고 비율·시간으로 보여준다.
- 예상 시험 점수에는 실력만 넣는다. 수행은 **경고**로만 붙인다 — *"완주율 62% — 아는 만큼 못 쓰고 있습니다."*

### A. 사후분포 — Wilson 점추정에서 Beta 구간으로

```
α = 1 + Σ w_eff,i · score_i          β = 1 + Σ w_eff,i · (1 − score_i)
m = α/(α+β)                          var = αβ / ((α+β)²(α+β+1))
M = cap × m                          구간 = cap × (m ± 1.96·√var)
```

- 표시는 `68`이 아니라 **`68 (52–81)`**
- 구간 폭 > 30점 → 숫자를 숨기고 **"판단 보류 — 증거 부족"**
- 구간이 넓으면 **앱도 모르는 것**이고, 그건 체감이 틀렸다는 뜻이 아니다.

### B. 감쇠는 점수가 아니라 무게에 건다

현재 엔진은 `M = Mraw × (0.4 + 0.6·Rnow)`로 **점수를 깎는다.** 이건 "실력이 떨어졌다"는 주장이고 근거가 없다. 실제로 아는 것은 "오래돼서 지금은 모르겠다"뿐이다.

```
decay(Δt_now) = exp(−Δt_now / S)      S = halflife@v1[f] × (g==='self' ? 0.5 : 1)
```

무게가 줄면 α·β가 함께 줄어 **구간이 저절로 넓어진다.** 점수가 내려가는 게 아니라 **불확실해진다.**

### C. 계층적 축소 — 안 푼 관을 형제로 추정

```
α_l = κ·ᾱ_parent + Σ w_eff·score          κ = 2 (가상 관측 2개)
β_l = κ·β̄_parent + Σ w_eff·(1 − score)
```

- `path[]`의 **바로 위 노드**를 부모로 잡는다. 깊이에 무관하므로 1차(4단)와 2차(2단)가 같은 코드를 쓴다.
- **measured / inferred 분리**: 그 관의 **실측 레코드에 한해** `n_eff = Σ w_eff`를 구하고, `n_eff ≥ 3`이면 measured. 부모에서 빌린 `κ·ᾱ`는 `n_eff`에 넣지 않는다 — 넣으면 모든 관이 measured가 된다.
- 학습 범위 밖(§5)은 형제가 없으므로 추정하지 않고 **"측정 불가"**로 둔다.

### D. 자기보고 관대도 — 개인별·stage별 추정

```
// 관 l 마다 두 사후평균을 따로 낸다 (자기채점만 / 객관채점만)
관대도 G = median_l ( m_self(l) − m_obj(l) )     // 두 증거가 모두 있는 관 l 들에서
w_self  = w_base × clamp(1 − 2G, 0.1, 1.2)
```

평균이 아니라 **중앙값**을 쓴다. 관 하나의 극단값이 전체 무게를 흔들면 안 된다. 표본 관이 5개 미만이면 보정하지 않는다.

**1차와 2차 관대도는 분리한다.** 2차는 자기채점 4단(85/70/50/30)이 기본이라 관대해지기 쉽고 1차 OX와 성격이 다르다.

기존 `calib`(`knowN`/`knowWrong`/`lowN`/`lowCorrect`)은 지금 표시만 하고 버려진다. 보조 입력으로 재활용한다.

### E. 법리 횡단 약점 — `principle` 집계

```
오답 → meta.chosen (선지 번호, 1-based) → option_meta[chosen − 1].principle → 관을 가로질러 누적
```

*"제23·31·47관에서 전부 「감가수정 = 회계 감가상각」으로 틀렸다"* — **관이 아니라 법리 단위의 약점**이 나온다. 명세의 지식그래프가 노리던 것의 실질을 콘텐츠 생산 없이 얻는다.

`meta.chosen`은 `quiz-progress-v1`의 `sel`을 계약 형식으로 옮긴 값이다. **한계를 정직하게 표시한다: 부동산·회계만.** 민법·법규·기출 본체에는 태그가 없다.

### F. 예측 검정 — 체감의 심판

응답 **전에** 모델이 `p = P(맞힐 것)`을 기록하고 사후 대조한다.

```
Brier = mean((p − y)²)      // 0.25 = 동전던지기. 낮을수록 좋다
```

매 응답이 검증 표본이다. 외부 데이터가 필요 없다. 리포트에 *"최근 200응답 예측오차 0.17"*.

**`p`는 응답 시점에 저장해야 한다. 소급 불가다** — 모델을 바꾸면 그때의 예측을 복원할 수 없다.

### 두 숫자로 분리

- **측정 실력** — measured 관만. 지금 점수의 정직한 이름.
- **예상 시험 점수** — §5의 시험 범위가 분모. inferred 포함, 구간 병기. 집계에 `pts`(배점)로 가중하고, stage별 합격 규칙(1차: 과목 40 / 평균 60)을 적용한다.

**`pts`는 여기서만 쓴다.** α·β에는 절대 넣지 않는다 — 배점이 큰 문제를 맞히는 것이 더 확실한 증거인 것은 아니다.

## 9. 2차 특유 처리

**① 채점 단위 분해.** 소물음마다 레코드를 남기고 `parent`로 묶는다(§4-1). 계산 소물음과 설명 소물음이 다른 `f`·`g`를 갖는다. **2차 채점 UI를 소물음 단위로 바꾸는 것이 이 계약의 가장 큰 구현 비용이다.**

**② 부분점수.** `score ∈ [0,1]`을 Beta에 그대로 넣는다(§8-A). 1차는 `score = correct ? 1 : 0`이므로 같은 식이 둘 다 흡수한다.

**③ 자기채점이 기본**이라 관대도 보정(§8-D)이 1차보다 중요하다. stage별로 분리한다.

**④ 모범답안 없는 논점** = `g:'none'`, 무게 0. 채점 근거가 없는데 점수를 매기지 않는다. 대신 **"채점 불가 논점 N개"**를 커버리지 결손으로 노출한다 — 콘텐츠 생산 우선순위가 여기서 나온다.

**⑤ 계층 구조가 다르다.** 1차는 `index_kind:'taxonomy'`(과목→장→절→관), 2차는 `'units'`(단원→논점). §8-C를 `path[]` 깊이 무관으로 구현해 두 구조가 같은 코드를 쓴다.

**⑥ `level`(L1~L5)은 무게가 아니다.** 사다리 진행 순서를 정하는 값이고, 증거 무게는 `format → f` 매핑이 정한다. 혼동하지 않는다.

## 11. 하지 않을 것

재제안 시 이 절로 거절한다.

- **IRT / Rasch 난이도 보정** — 기출 난이도의 79%가 값 3이라 정보가 없다.
- **지식그래프 신규 구축(항목·자질 축·혼동짝)** — `principle` 태그가 이미 그 일을 한다.
- **DKT / SAKT 등 딥러닝 지식추적** — 단일 학습자 데이터로는 과적합만 한다.
- **매 문항 확신도 입력** — `assisted`가 이미 "알고 맞혔나"의 답이고, `produce`는 애초에 찍기가 불가능하다.
- **가중평균 U/R/A 유지** — 증거 종류를 지우는 구조 자체가 문제의 뿌리다.
- **점수에 감쇠 곱하기** — 오래된 것은 낮은 것이 아니라 모르는 것이다.
- **배점을 증거 무게에 곱하기** — 배점이 큰 문제를 맞히는 것이 더 확실한 증거는 아니다.
- **포기 범위를 분모에서 빼기** — 버려도 시험에는 나온다.
- **완주율·선구안을 실력 점수에 넣기** — 다른 축이다.
